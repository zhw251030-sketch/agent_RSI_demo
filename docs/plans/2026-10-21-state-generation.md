# 冷启动来源生成实施计划

**目标：** 完成8槽受控OpenHands冷启动来源生成、先冻结后静态分析、真实请求来源审计和双端归档；固定未来配对分配但不启动评分或策略学习。

**设计依据：** [冻结协议](../protocols/2026-10-21-state-generation-v0.1.md)。用户已授权继续上一轮明确的下一步，复用现有模型与持续同步。沿用仓库docs/plans惯例；在当前会话用独立子任务并行实现和审查。

**实现边界：** 新增模块，旧源码/档案不改。核心不导入SDK和执行器；SDK只有提交/finish；runner冻结来源、账本及会话树；审计只读请求与源码，不执行候选。生成有实际API消耗，单独账本最大8请求/5元。

- [ ] `rsi_eval/state_generation.py`、生成配置/提示与核心测试：先失败测试，固定8槽、匿名投影、旧公开输入绑定、一次持久化提交。
- [ ] `rsi_eval/state_generation_agent.py`与SDK测试：严格业务字段、单请求、实际输入/响应/SDK收据，关闭环境工具与配置发现；服务器真实SDK模拟验证。
- [ ] `scripts/run_state_generation.py`、`scripts/analyze_state_generation.py`与测试：先失败测试，来源与运行冻结、失败关闭、全量保留、后置静态分析及真实请求审计。
- [ ] 独立审查、相关测试、实现提交与服务器快进同步；先prepare-only再按冻结版本执行一次8槽有界生成，失败不补抽。
- [ ] 原始文件归档、双端审计与必要篡改验证；结果/操作/验收文档、四部分状态、费用汇总；提交推送并核验三处一致。

关键取舍：使用新的模型冷启动提交，避免手工注入故障预设收益；采用匿名符号接口，代价是可能得到普通模板或不适合的公式，必须照录。未来执行权限与新角色评分器单独实现，不通过修改旧manifest绕过历史访问规则。
