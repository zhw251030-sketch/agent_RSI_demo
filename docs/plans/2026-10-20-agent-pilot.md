# 有界真实 Agent 小试实施计划

日期：2026-10-20。用户已要求继续上一轮明确提出的有限调用 Agent 小试；本计划执行该授权，不扩大为正式机制对照或测试集评价。

**目标：** 在固定 MiniMax-M3 权重和固定修订提示下，分别运行一个 Spanner 与 oscillator1 会话，完成初始候选评价、模型提出修改、工具执行、反馈及可追溯记录。

**结构：** OpenHands SDK 1.55.1 的 Agent/Conversation 只使用一个提交候选工具及 Finish。可信工具固定任务集合、候选数和选择规则，重用已有隔离执行器。模型客户端在实际 transport 前登记预算，关闭自动重试、环境插件、技能、MCP、压缩器与额外模型角色。运行只使用允许的开发数据。

## 实施步骤

- [ ] 核对服务器 SDK 的真实调用、工具初始化、系统提示、事件和用量接口；核验官方 MiniMax 单价。
- [ ] 固定任务包、弱起始候选、选择规则、模型与预算配置。每会话最多 3 个模型候选和 4 次模型请求，两会话共享 8 次请求上限；单次输出 4096 tokens。本轮保留 5 元预算，不超过既有 300 元项目预算。
- [ ] 先测试预算耗尽、失败请求计数、重启持久化、候选数量/任务限制和选择规则，再实现账本和批量受控工具。
- [ ] 实现真实 Agent runner：空工作区、定制提示、关闭环境插件/工具注入，保存模型请求/响应、事件、源码、所有反馈及 first/last/best；异常也产生记录。
- [ ] 用假的模型传输进行无付费 Agent 往返，证明 SDK 实际调度使用受控工具，并检查预算在网络发送前生效。
- [ ] 检查并同步代码，再在服务器运行两类真实小试；不为获得好结果擅自增加候选或重跑。
- [ ] 根据实际输出核验记录、解释失败或改进及证据边界，更新说明/状态并同步 GitHub 与服务器。

## 评价与边界

规划每个候选固定检查 2 个提示题和 8 个开发题，按开发成功数、提示成功数、较早候选选择。符号仅使用 oscillator1/train，按最低有限 NMSE、较早候选选择。报告初始、最后和开发最优，全部是开发结果。固定策略 S 不自我更新；变化的是产物 P。没有测试成绩、泛化结论、统计显著性或 RSI 有效性结论。

用量基于供应商响应记录，费用按已核验公开价估算；历史连接探针部分用量缺失，不能冒充完整账户账单。持久预算账本限制本轮进程的尝试数、输出、输入大小和保守预留，不控制 Canvas 或其他项目的消费。
