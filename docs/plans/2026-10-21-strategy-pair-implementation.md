# 策略调度实现计划

用户已要求继续上一轮明确的SDK控制器、阶段调度器与36槽模拟验收。设计依据为新strategy-pair-v0.1协议，旧协议/配置/提示/记录保持不变。

1. SDK控制器：新增strategy_pair_agent/controller及测试；严格一次提交、固定packet、保存原始请求/响应与SDK接受。模拟provider验证实际SDK行为。
2. 总账：新增strategy_pair_budget及测试，使用固定36slot全局账本，预留前拒绝越序/超额/重用，未知usage全局停止。
3. 调度器：新增strategy_pair_run及测试，注入session runner/executor factory，连接基线、共同上下文、提案冻结、选择绑定和双S*门槛；评价投影单独实现。
4. 准备与审计：新增运行入口和模拟执行器，校验旧236运行文件与原始档案；冻结新运行清单及实际SDK模板，核对整轮请求/响应/接受/事件顺序，加入重算哈希后的篡改负例。
5. 双端验证：本机逻辑测试、服务器完整SDK测试及36槽模拟；将人工记录与研究账本严格区分，保存全部原始证据。
6. 交付：独立审查、运行相关回归、实现提交；干净版本生成正式模拟证据；归档与说明提交、GitHub推送、服务器只快进同步并复核三处HEAD。

验收不以测试数量代替研究效果。本轮只交付运行控制与模拟证据；任何真实运行都需要独立报告实际请求、候选执行、费用及停止状态。
