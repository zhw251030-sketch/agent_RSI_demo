# 可执行主张检查：SDK 接口修复轮 v0.2

日期：2026-10-20（Asia/Shanghai）。本轮在新的付费请求之前冻结，是独立运行目录，不恢复 v0.1。

## 为什么另开版本

v0.1 在 8 次请求后因设施问题停止：额外格式审查直接验证 provider 原始工具参数，未遵循 OpenHands 对 summary/security_risk 的外层字段处理，导致有效提交被错误标记 submission_schema。工具只声明 list[dict]/dict，未向模型提供完整引用结构；五个实际生成候选的八项主张全部写成错误引用格式。原始请求、失败及停止决定全部保存，不能作为有效的反馈效果对照。

停止记录：`runs/checked-feedback/20261020-checked-feedback-v01/operator-stop.json`。停止时第八次请求在途，允许其正常结算，后续预算预留被阻止。实际 8 次请求、61537 tokens、已知估算 0.2010162 CNY、保守预留 0.7970802 CNY；未知用量为 0。初始评价四组，实际生成只涉及前两组。

## 事前固定的改动

1. 格式审查与已安装 OpenHands SDK 1.55.1 的外层工具字段解析一致。测试响应使用真实 SDK 发布的外层参数，验证合法字段不产生错误提示、未知业务字段仍被识别。当前 SDK 会移除 summary/security_risk；在未启用 security_analyzer 时，即使这两项值不规范也可能被忽略，额外观察器遵循该行为，不能制造与实际执行不同的拒绝。错误标记只影响下一次反馈，不另行阻止执行或改写评分。
2. 为 claims 和 prediction 明确发布嵌套 JSON schema。reference 是包含 session_id/candidate_id/candidate_sha256/task_id/version/scope/key 的**平铺对象**，不能再包一层 binding。运行时核心谓词与四种结果状态不变；语义错误仍由检查器反馈。两组共享完全相同的结构说明。
3. 新版本使用新配置/策略标签、独立账本和运行 ID。四组全部从原弱起点重新开始；不将 v0.1 的源码、成绩、主张或语言解释加入新会话。

除此之外，[v0.1 协议](2026-10-20-checked-feedback.md) 中的两个任务范围、四组顺序、模型设置、三候选/四请求上限、检查可见性唯一干预、评分与选择规则、绑定、容差、字节限制及不读封存集要求均继续适用。

## 修复轮预算与停止

新轮最多 16 请求、每会话≤4、每会话≤3候选，输出≤4096 tokens/请求，输入≤98304字节，保守 token 预留≤3000000，新成本预留≤9 CNY。加上已停止 v0.1 的保守预留 0.7970802 CNY，本次继续工作合计预留不超过 9.7970802 CNY，仍在原项目 300 CNY 内。旧账本不删除或重置。

运行 ID：`20261020-checked-feedback-v02`。固定顺序仍为 planning_hidden、symbolic_checked、planning_checked、symbolic_hidden。设施失败、未知用量、预算拒绝继续停止后续会话，无恢复与自动重试；格式错误消耗原请求额度，不额外补偿。若再次不能完成，应如实报告，不把人工修补或新一轮结果混成同一实验。

## 可解释范围

修复轮只能检验本次接口与有界反馈流程是否能运行，及这四个探索轨迹中出现了什么。它仍基于已用于开发的任务与起点，且受 v0.1 调试经验影响；不是独立预注册检验，不能排名、证明因果机制、泛化或策略 S 更新。报告同时包含 v0.1 失败和 v0.2 全部条件、费用及主张覆盖。
