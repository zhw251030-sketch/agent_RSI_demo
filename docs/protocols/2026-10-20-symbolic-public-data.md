# 符号侧当前数据接口：LLM-SR 公开原始任务

本文件覆盖旧 `2026-10-20-symbolic-interface.md` 中关于当前起步数据来源及列顺序的建议。用户要求公开替代后，当前采用 LLM-SR 原论文数据，而非 LLM-SRBench。方法和完整协议仍未冻结。

- 官方源码固定为 `41c212312df6c16d936c9cb395356a62774c47e3`。来源、每文件哈希和数据结构见 `configs/tasks/downloads-v0.1.json`。
- 起步任务为 oscillator1 和 oscillator2；另外两个问题只是库存，不自动分配实验角色。
- oscillator1 输入 `(x, v)`，目标 `a`；oscillator2 输入 `(t, x, v)`，目标 `a`。所有 CSV 的输出均为最后一列。
- 候选可以沿用 `equation(<输入数组>, params) -> 一维预测数组` 的设想，常数只能在允许的训练数据上拟合。尚未接入公式执行器，不能把下载完成视为已跑通参数优化。
- 保留官方 train/test_id/test_ood。先在 train 内明确定参拟合、产物开发反馈和策略选择方式，再开始自适应实验；官方文件没有替我们给出这三种角色的独立划分。
- 不从封存 test_id/test_ood 产生开发反馈，不使用它们筛选策略、候选或资源分配。本次只做全体文件完整性、结构与精确重叠审计，没有测试成绩。
- 振荡器数据来源于轨迹；原 CSV 不为所有任务保留完整轨迹/初值身份，不能随意宣称随机行划分具有独立性。需要在正式实验前记录能支持的划分假设，必要时选用按系统分组的扩展任务。
- 更新对象继续区分产物 P（公式程序）和策略 S（如何选择下一步修订）。本次下载并未新增共同更新规则。
- 原始源码和论文可含答案及参考程序，未来 Agent 不可直接读取 vendor/ 或全部 data/。当前只是文件组织，隔离执行和受控数据视图尚未实现。

验收与选择理由见 `docs/operations/task-data.md`。原论文的结果不直接移植到本项目，也不能把两个方程上的多次运行当作很多独立任务。
