# 冷启动产物生成与后续配对分配协议 v0.1

## 本轮可执行范围

生成8次新的冷启动提交，不预先保证8个不同、可运行或有待改进的程序。每槽一次MiniMax-M3请求，无旧源、修订策略或任务成绩。所有提交与失败都保留，不按语法、成绩、重复或难度补抽。本轮不执行候选、不拟合公式、不运行probe、不更新S、不读任何符号CSV或封存任务。

此前接受规则及任务角色见 `2026-10-21-goal-alignment-v0.1.md`。用户已授权继续既定下一步、复用模型及300元以内项目预算。此次单独保守预留上限5元，不重置历史费用或未知usage；计价沿用项目账本固定估算参数，不代表新查询的实际账单。

模型请求不包含槽位ID、角色、实际task ID、数据哈希、旧候选、旧分数或参考解。规划请求只用公开Spanner动作契约和历史seed0/problem0、problem1的两个公开TaskView，四槽完全相同。符号只给 `u0…uN`、维数、函数/数组接口、常数拟合约定和一般算子约束，不提供方程名、物理描述、原列名、数值行、参考式或训练统计。相同维数的两次符号请求完全相同。输入维数仍是先验，本方案不声称消除预训练记忆。

每槽最多1次模型请求、1次提交；最大输出8192token，完整请求最大65536 UTF-8字节，源码最大16384字节，参数数目0–16（规划必须0）。总请求8，累计保守token预留1000000、费用预留5元，固定估算输入/输出每百万token 2.1/8.4元。禁自动重试、恢复、fallback与额外摘要调用；使用现有OpenHands SDK 1.55.1、MiniMax-M3配置，凭据不进记录。

## 冻结顺序和失败处理

1. 提交并核验生成代码、协议、配置、提示和测试；记录干净Git版本及全部运行文件哈希。
2. 在首个请求前冻结8槽的宿主分配、模型可见任务包、两个公开TaskView来源、现有历史源码索引和模型设置；任务角色绑定既有清单。
3. 顺序请求，只作业务类型/大小/参数界限验证和原样持久化，不按Python语法或代码质量决定补抽。保存真实发送请求、provider响应、usage、SDK接受的业务字段、源文件及记录。
4. 全部槽位尝试结束，或基础设施/未知usage中止后，写入所有槽位的状态，冻结整个会话文件树。尚未开始、无有效提交、业务拒绝和已保存源码分开记录；禁止伪造源码或将未知费用置零。
5. 只在源码树冻结之后，静态解析源码、检查入口签名、计算源码与AST重复关系。语法错误、与旧源码碰撞、组内及跨角色重复均如实保留。记录静态可解析不等于执行成功，AST不同也不证明语义不同。

已有已知usage的无提交/格式错误消耗该槽后可继续下一槽；未知usage、未结算请求、宿主错误或运行文件变化停止后续。停止轮不恢复。本轮0候选/任务/probe执行不靠总结字段自行认证：代码不得导入执行入口，测试必须设置会抛错的执行/网络替身，独立审查核对调用链。

宿主异常只记录异常类型，不记录可能含敏感内容的异常文本；完整性仍成立时冻结已生成的前缀。若冻结输入或运行文件已变化，则状态为 `integrity_failed`，仅保存 `unverified-source-snapshot.json`，不出具可信源码冻结或静态分析结论。

## 后续配对分配（本轮只冻结分配，不执行）

学习仍限于既有seed0、oscillator1的归档开发材料。采用现有有限策略表示：8条通用规则中有序选择4条，S0及renderer由 `rsi_eval/revision_policy.py` 固定。首版不声称完整GEPA复现或更新器自改写。后续实施前须锁定具体学习包、actor/更新提示全文、真实请求投影、角色执行适配和评分器；此分配协议不等于那些接口已就绪。

设置2个独立的策略提案请求重复：每个都从同一S0和同一冻结学习包开始，不递归继承前一个S，也不从两个提案中择优。它们是模型调用重复，不是两个独立学习数据集。每个重复的固定臂还发出一次相同额度的shadow更新请求，输出仅归档，绝不进入S0、修订上下文或记忆。真实token和费用分别报告；相同调用/输出上限不等于实际计算量完全相等。

每重复包含：1真实更新、1shadow更新、4选择状态×2策略臂×1修订、4评价状态×2策略臂×1修订，最多18请求；两重复共36。连同本轮8次来源生成，两阶段最多44请求。未来36次请求需单独账本、上限12元；本轮不会创建或消费这个账本。最大请求不是必须耗尽的目标。

选择状态为P-select-1/2与S-select-1/2。根据 `goal_alignment.select_strategy` 的完整配对结果接受S1或保留S0；选择期间不能继续改写S1。评价状态为P-eval-1/2、S-bact-eval-1与S-stress-eval-1，只评价冻结后的S*。若S1被拒，S*=S0，两臂相同策略的随机结果差不能算策略更新收益。缺源或缺测量保留在槽位中，选择不完整不能晋级，不补抽。

规划修订反馈仅使用seed0旧公开/开发题；选择19题和评价63题仅用于宿主评分，成绩不回传同一修订。符号选择/评价方程的train数据可在对应阶段为该起点产生拟合反馈，但任何评价方程的基线评分及反馈构建必须等S*冻结之后；评价成绩不回传S选择。所有官方test/test_id/test_ood仍封存。新的角色执行适配必须明确授权并验证真实数据路径，不修改旧执行器权限或伪装旧角色。

统计报告保留每个策略提案、起点谱系、任务、候选、缺失和成本。规划63个实例的成功数不是63个独立策略学习重复；同一方程不同公式不是独立方程；train拟合不称独立预测。跨角色源码/AST重复时评价只能支持新实例行为观察，不能宣称新程序起点泛化。两次提案只支持开发观察，不作显著性或普适性结论。
