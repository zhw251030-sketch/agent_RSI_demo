# 两类任务共用的研究接口与证据边界

日期：2026-10-20。性质：后续实现的准备规范 v0.1；接口与对照尚未通过真实 Agent 实验。任务来源与具体边界见[规划接口](2026-10-20-planning-interface.md)和[符号接口](2026-10-20-symbolic-interface.md)。

## 本项目究竟让什么发生改变

固定基础语言模型 M。每次它读到任务、当前产物 P、执行反馈 F 和修订策略 S，提出候选产物 P'。执行器检查 P'；另一个明确记录的步骤可以提出策略 S'。S 是“以后遇到类似证据时如何修订”的指导，P 是这次可执行的程序或公式。

例如规划侧的 P 是为同域实例生成动作序列的 Python 函数，符号侧的 P 是带常数的公式程序。策略 S 可以指导先定位哪类错误、怎样提出候选或复核已有成功行为。具体策略表示和更新算法还未选定，不能因写出了接口就称为新方法。

```text
公开任务 + P + S
        ↓ 固定 LLM（后续接入）
      候选 P'
        ↓ 任务执行器
      可见反馈 F
        ├──→ 选择/修订产物
        └──→ 候选策略 S' → 在独立选择状态上检查 → 保留或退回 S

冻结的产物和策略 → 独立评价端 → 最终结果（不反馈到上述选择）
```

OpenHands 位于模型与工具调用这一层。它不替代规划合法性验证器、公式数值评价器，也不自动实现策略更新或防止测试信息泄漏。

图中的独立策略选择分支是后续目标，当前准备清单没有启用它：规划侧 `strategy_selection_set` 为 null，符号侧内部选择划分也未确定。首个拟议比较仅从共同父产物出发进行一次修订，然后做封存评价；任何自适应候选/策略筛选都必须先定义独立选择规则，不能使用 30 个规划测试实例筛选。

## 共同记录契约

后续两套适配器至少保存下列信息，字段名是本项目准备规范，不是声称上游已经采用的统一 API。

| 对象 | 要保存什么 | 用途 |
|---|---|---|
| TaskView | task_id、任务来源版本、公开说明、允许访问的数据引用 | 说明 Agent 实际看到了什么 |
| Candidate | candidate_id、parent_id、产物源码与哈希、strategy_version | 能重建每次修改来自哪个起点 |
| ExecutionFeedback | 执行状态、可见错误/分数、反馈所用样本 ID、时间 | 区分程序错误、任务失败与评价条件 |
| StrategyRevision | 旧/新策略、支持与反驳证据 ID、选择结果 | 检查形成了什么经验，是否被保留 |
| BudgetLedger | 模型调用数、输入输出 token、候选数、执行次数和耗时 | 控制额外尝试带来的收益，后续另记实际费用 |
| HiddenEvaluation | 冻结版本、未参与选择的状态/实例、最终指标 | 检查改进能否延续到新状态 |

记录所有候选，包括失败、弃用、回退和超时。仅保存最终最优公式或规划程序，会丢掉“为什么改好/改坏”的证据。

## 最低比较结构

比较应从同一父产物、同一任务信息和可用反馈开始：

1. 固定策略，但保留同样的产物搜索过程。
2. 执行反馈直接指导产物修订，用来观察普通调试的作用。
3. 成熟的共同策略更新器；GEPA 式方法仍是候选，并未在本轮选定实现。
4. 只有观察到可重复问题后，才加入针对该问题的机制改动。

策略更新调用也计入总预算。不能一组额外调用模型再把最终更高分完全归因于策略质量；需同时报告质量随累计调用/token/执行成本的曲线。最终重复次数与预算在小试观察变异性之后冻结，不在零实验时编造功效保证。

评价时还要“带走策略、重置产物”：让旧 S 与新 S' 在未用于选择的新父程序或新父公式上修改，才能检查策略的后续作用。重复使用原来的最佳成品，只能说明成品搜索进展。

## 信息隔离分三层落实

- **任务实例层**：规划的提示/开发实例与官方测试实例分开；符号的拟合观测、内部选择观测和官方 ID/OOD 观测分开。
- **修订状态层**：选择策略用过的父产物/状态与检验策略作用的父状态分开。新的随机种子不自动保证独立。
- **任务族层**：跨域或跨方程泛化需要另外的域/结构族留出，不能由一域多实例或一条公式多观测点代替。

文件分目录只是准备步骤。运行 Agent 时，还需要执行器的访问权限或容器挂载真正限制其读取评价端文件。当前本地终端工具直接拥有宿主账号权限，所以本轮没有声称实现了这一隔离。

## 本轮完成与下一个运行门槛

本轮交付任务来源清单、源码接口审查和无模型的 OpenHands 工具验证。规划与符号执行器、策略更新器、数据适配和正式评价尚未实现。

启动首个真实 Agent 小试之前，需做到：任务材料实际验收；生成代码的隔离执行就绪；模型接口与预算配置完成；至少一条端到端基线及反馈/评价隔离通过检查。符号数据仍需合法访问权限；本轮未代替用户接受数据访问条款。
