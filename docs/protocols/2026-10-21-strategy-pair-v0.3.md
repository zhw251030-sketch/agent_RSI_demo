# 策略配对轮 v0.3：只公布单个业务提交工具的独立运行

本协议延续 [v0.2](2026-10-21-strategy-pair-v0.2.md) 与 [v0.1](2026-10-21-strategy-pair-v0.1.md) 的研究设计、学习包、八份来源、任务角色、规则目录、36 个位置、选择规则及预算。用户已明确要求继续完成下一步。此次修复上一轮实际暴露的单步提交与 SDK 默认 finish 工具冲突；measured-v01/v02 保持停止，不恢复、不补抽、不追认未接受的源码。

## 实现范围与不变量

1. 单步策略 Agent 仅公布 submit_policy，单步候选 Agent 仅公布 submit_candidate。使用 SDK 1.55.1 的 include_default_tools=[]，不向模型公布 finish。
2. 新 agent 系统提示明确只允许一次业务工具提交，不调用 finish；原 236 文件内的用户任务提示、历史学习包和规则内容不变。模型权重、温度、超时、输出限制、tool_choice 等既定设置不变，不额外强制选工具或改变并行调用配置。
3. 工具允许表、实际 SDK 请求模板、网络前请求绑定和事后审计必须与单工具表一致。原始响应继续只接受一个合法业务调用；拒绝 finish-only、业务+finish、finish+业务、重复业务、未知工具、非法元数据或无实际调用，拒绝时不发生部分接受。
4. 新 agent 版本标识为 strategy-pair-agent-v0.2；审计由宿主固定 expected_agent_version，默认要求当前 v0.2，不允许待审计记录自行选择旧分支。历史 v0.1 双工具请求仅在调用者明确指定历史版本时回放，不能作为新版本接受任意工具集合的依据。业务字段/元数据投影保持既有严格校验。
5. 不改变共用历史 pilot_agent/two_stage_agent，不修改旧候选或分数，不把本轮或前两次停止信息添加到冻结的学习包。

## 验证与冻结顺序

先以实际 SDK 构建请求的测试证明旧实现仍公布 finish，再实现修复。新测试覆盖 update/actor 两条路径的单业务成功以及非法调用的原子拒绝；已有元数据、原始记录绑定、预算、阶段顺序和审计测试继续运行。保存 RED/GREEN 日志，模拟用量不计真实研究。

在代码、测试和本协议提交后，从干净版本创建 sdk-preflight-v03；用实际 SDK、假 provider 与人工测量走完 36 个位置、716 条测量和两个选择回放。核对最大请求预算字节、实际派发与接受、共同输入、失败停止、评价门以及同一运行文件清单。模拟仅认证覆盖范围，不保证模型输出成功或机制有效。

旧 236 文件及 693 份历史原档按原哈希校验；旧 254/256 文件运行版本按各自 Git 提交与旧冻结清单校验。两次旧模拟、两次旧真实轮及外部执行记录保持原样。新后继修改不要求等于旧代码，但不得改写旧冻结证据。

## 本次真实执行范围

完整模拟与审计通过后，只另开一次 measured-v03，使用新目录、新账本和同版本 readiness。先四次策略提案，再执行共享选择基线及 16 次选择修订；两个重复分别完成 S* 冻结后，才允许任何后续评价起点的基线、反馈或评分，再进行 16 次评价修订。

每位置一次、180 秒、零重试；最多 36 请求、8,192 输出 tokens、98,304 输入预算字节、保守费用预留上限 12 元。缺失/非法提交、基础设施故障、未知 usage 或冻结校验失败即停止，不补抽。可测量的候选任务错误按原规则记分，不自行修代码或改变奖励。

如果本轮停止，保存完整尝试、未启动位置、用量与失败原因；本次不再追加另一个真实后继轮。项目人民币 300 元预算继续有效，旧两笔未知 usage 保留。新模拟与任何离线诊断不得混入研究账本。

## 研究边界

前一轮已执行四份选择起点，因此本轮沿用的是冻结但已被研究者看过选择结果的来源，不能宣称全新盲测来源。四份后续评价起点尚未执行；不得提前执行，也不得用其结果修改学习/选择规则。两个重复仍复用同一个历史学习包。

策略提案接受、理由可信、任务收益与后续泛化分别报告。一个规划领域、四个方程与 train 拟合成绩不构成普适性证明。300 个官方规划测试及 8 个符号测试 CSV 继续封存；本轮后续评价仍只使用冻结的允许任务角色。
