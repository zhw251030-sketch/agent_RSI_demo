# 策略配对轮 v0.2：SDK 元数据契约修复后的独立运行

本协议延续 [v0.1](2026-10-21-strategy-pair-v0.1.md) 的研究设计、学习包、任务划分、36 个位置、选择规则与预算，只修正宿主 SDK 接收接口及对应模拟覆盖。用户已要求继续修复并执行下一步。`measured-v01` 保持停止，不恢复、不补抽、不改写原始响应或接受状态。

## 唯一实现变更

策略工具公布的 `summary` 与 `security_risk` 为 SDK 可选元数据。原始 JSON 必须先严格解析，拒绝重复键、未知字段和非有限数；元数据须匹配明确类型和 SDK 风险枚举，随后仅将业务字段交给策略/源码接受器。元数据不进入四规则策略或源码，不影响选择目标；完整元数据保留在原始响应哈希绑定内，审计重新验证相同投影。新的策略专用 schema 需解析属性中的引用，禁止发送悬空 `$ref`，不改历史共用的 `two_stage_agent.py`。

更新和修订两条路径均验收：省略元数据、合法元数据、可空 summary、非法风险值或类型、未知键、重复键、无效业务值。假 provider 必须通过实际 SDK 工具派发验证；完整 36 位置模拟混合带/不带元数据的回复，并确认请求预算仍未超过 98,304 字节。

## 冻结与执行顺序

1. 修复与测试提交后，从干净提交建立 `sdk-preflight-v02` 新运行冻结清单。旧 236 个基础运行文件及历史数据来源继续逐字节核验；旧 254 个运行文件的历史内容由原 Git 提交和旧冻结清单核对，不要求后继代码仍等于旧实现。
2. 实际 SDK、假 provider、人工执行记录完成 36 请求位置/716 测量、两次选择回放和审计，产生同版本 readiness。模拟用量与接受均不计研究。
3. 用新目录 `measured-v02` 和新账本执行独立真实轮，保持 MiniMax-M3 权重、模型设置、学习材料、提示、任务角色及规则目录不变。四次更新、16 次选择、两个 S* 冻结、16 次评价；任何评价起点的基线/反馈只能在两个 S* 冻结后执行。
4. 每位置一次；180 秒、零重试；最多 36 请求、8,192 输出 tokens、98,304 输入预算字节，保守费用预留上限 12 元。缺失/非法提交、基础设施问题、未知 usage 或冻结校验失败均停止，不补抽。可测量的候选任务错误按原规则记分。

本次只运行一个独立后继轮。即使停止，也保存尝试、未启动位置、用量及失败来源，不修改规则继续同一轮。旧未知费用不抹除，整个项目 300 元预算继续有效。

## 结论边界

接口修复与模拟完成只说明运行路径通过验收。真实结果必须另行报告；不能把模型原始规则文本、模拟接受或检查通过视为任务收益。两个重复复用同一个历史学习包；一个规划领域、四个方程以及 train 评分仍不足以证明普适性。300 个官方规划测试及 8 个符号测试 CSV 继续封存。
