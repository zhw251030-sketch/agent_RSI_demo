## 各文件承担什么

| 文件 | 职责与原因 |
|---|---|
| `rsi_eval/strategy_pair_controller.py` | 更新与修订分别只接受四规则ID或完整源码；拒绝重复字段、越界参数及从正文臆造提交；解释只归档。 |
| `rsi_eval/strategy_pair_agent.py` | 真实SDK负责组装请求和派发工具，记录响应、SDK派发与宿主接受；一次请求成功提交后正常的迭代上限提示不会误判为失败。 |

| `rsi_eval/strategy_pair_budget.py` | 一个持久总账管理36位置，解决旧总账最多16会话的问题；每位置一次、共享费用上限、未知usage停止。 |
| `rsi_eval/strategy_pair_run.py` | 执行四提案—共享选择基线—16修订—双S*冻结—评价基线—16修订的顺序，连接旧接受器和新评价投影。 |
| `rsi_eval/strategy_pair_audit.py` | 执行前核对实际请求/响应/SDK工具/接受/源码，运行后回放顺序、原始测量、策略选择与比较；声明不能代替测量。 |
| `rsi_eval/strategy_pair_preparation.py` | 核验旧236文件与历史输入，另冻结本轮新增运行文件；新文件增加不等于旧准备包被篡改。 |
| `rsi_eval/strategy_pair_simulation.py` | 只能写明确标记的人工记录，不能运行源码、解析任务数据或使用真实评价凭证；模拟分数/usage不计研究账本。 |
| `scripts/run_strategy_pair.py` | 串联准备、模板捕获、总账、实际SDK、执行前审计与最终审计；正式运行需同一代码的完整模拟凭证。 |

## 实验到底比较什么

四个update请求共用同一个24条历史学习包。r1/r2各提出一个S1，也各有一个只归档的shadow提案，用于控制更新请求额度；不从两个S1中挑最好者。两重复不是两个独立学习数据集。

每个重复在四个选择状态上比较S0与自己的S1，共16个actor请求。两臂共享起点与反馈，只有四条修订规则可能不同。选择器按事先确定的任务收益规则决定晋级；任何退化或不确定阻止晋级。S1被拒时S*=S0。

两个S*都冻结后，才为另外四个评价起点建立反馈并生成16个终稿。即使一个评价规划程序只是先去seed0学习题上获取反馈，也属于这个后置阶段。评价结果不再改变S*；同策略调用之间的随机差异明确标记no_policy_change。

## 模拟说明与命令

```bash
.venv/bin/python scripts/run_strategy_pair.py --run-id sdk-preflight-v01 --simulate
```

完整模拟走真实SDK和工具校验，但在provider边界返回预定回复，并禁止网络连接。人工执行器只按任务元数据写716条虚构观察，不调用sandbox、VAL或拟合器。4次更新与32次修订的模拟usage及预留金额不计研究消费。模拟的保留/晋级也不算真实S学习。

从干净实现提交完成模拟、请求大小检查和原始记录回放后，会生成`readiness.json`。未提交开发模拟可用`--allow-dirty`，但不会获得真实运行凭证。输出目录一旦存在不重用，不恢复中止模拟。

准备模式不加载SDK或密钥，也不发请求：

```bash
.venv/bin/python scripts/run_strategy_pair.py --run-id preparation-v01 --prepare-only
```

独立真实运行使用新目录和新总账，入口会先重验完整模拟、运行文件、请求模板和历史输入，随后才读取已有服务器凭据：

```bash
.venv/bin/python scripts/run_strategy_pair.py --run-id measured-v01 --run \
  --certificate runs/strategy-pair/sdk-preflight-v01/readiness.json
```

这只是运行方式，不表示真实轮已经启动。实际状态、验收与本轮结果以对应带日期报告为准。

## 预算与停止规则

36次总请求、每位置一次，输入预算JSON98,304字节、输出8,192tokens、180秒、零重试，总预留不超过12元。历史估算费率不等于实时价格或账单；预算约束只覆盖本运行器，不覆盖Canvas或其他项目。

非法/缺失提交、基础设施故障、预算或冻结文件检查失败、未知usage都会停止后续位置；任务本身的错误另作实测结果保留。停止后不补抽、不覆盖、不重新命名成完整成功。未知usage不记零，错误摘要只保留安全异常类型。真实研究轮的代码版本、请求数、实际候选执行和费用需另行报告。

接口与哈希审计是可信客户端内的记录一致性检查，provider派发证据止于SDK到LiteLLM的调用边界，未观察后续HTTP序列化；不是供应商签名、独立时间戳、整个二进制环境证明，也不证明RSI有效或跨任务泛化。
