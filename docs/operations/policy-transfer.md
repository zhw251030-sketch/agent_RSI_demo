# 首次更新修订策略S：做了什么，结果说明什么

2026-10-20；运行版本`154bc39`。**本轮已经让固定权重的模型从旧失败经验中更新一次修订策略，再把策略用于不同的旧父产物。** 共13次真实请求、11个实际执行的新候选；新策略在符号状态上两次都得到较低训练误差，规划一次成功、一次失败。它是一个真实可复查的开发实验，还不能证明方法稳定、普适或达到正式测试效果。

## 1. 与上一轮相比，真正多了哪一步

上一轮[固定起点对照](paired-repair.md)改变的是模型是否看到明确的检查结果，修订提示S始终固定。本轮增加了“经验→策略→另一状态上的修订”这一步：先向模型提供两张历史经验卡，让它改变以后修订时优先考虑的规则，再冻结该策略用于评价。

这里的S暂时采用一个受限但明确的表示：从人工写好的8条通用规则中选择4条，并决定顺序。规则涉及格式契约、最早失败、环境语义、指标范围、编辑对应、替代解释、预测幅度和保留正确行为。模型没有生成任意新规则，也没有修改自身权重或更新算法。

真实变化为：`S0=[R03,R04,R06,R08]`变成`S1=[R03,R04,R02,R06]`，加入“先处理最早可观察失败”的R02，移除“保留正确行为、最小完整修复”的R08，R06后移。原始选择与理由见[提交文件](../../artifacts/policy-transfer/2026-10-20/v01/policy_update/policy-submission.json)，实际应用的规则序列见[S1](../../artifacts/policy-transfer/2026-10-20/v01/policy_update/policy-S1.json)。

主机只把预先定义的规则正文按这个顺序交给评价模型；模型自由撰写的更新理由不会进入评价提示。这让策略变化可追踪，也限制其表达能力。更新理由本身仍有错误，例如把候选公式修改解释成改变环境定义，以及遗漏R01也覆盖输出格式；本轮保留原始S1，不人工修补后再评价。

## 2. 经验来自哪里，为什么评价换两个起点

| 用途 | 选择的真实旧状态 | 为什么选择 |
|---|---|---|
| 更新经验U-P | 上轮规划检查组：计划长度从1变11，但仍在第0项输出语法失败；0/10→0/10，预测至少增加2未达到 | 能区分“产物变长”与“最早失败被修复” |
| 更新经验U-S | 上轮符号检查组：train NMSE约0.096392→0.095889，下降约0.000504，未达到预测0.002 | 有小幅真实改善，同时能检验是否从预测落空中得到可靠经验 |
| 评价起点E-P | 更早的规划B第3份程序，0/10；公开例执行7步后使用不存在的反向link | 与U-P输出格式失败不同，需要修复语义及取用多个工具的策略 |
| 评价起点E-S | 更早的符号C第2份公式，线性带截距，train NMSE=0.09591726394116994 | 与U-S所修订的二次位置公式不同，可观察经验是否用于另一个父公式 |

这些都来自模型真实提交的归档，不是本轮人工制造的错误。加载器钉住源码和诊断哈希并验证评分一致性，直接复制旧基线，不重跑它。更新包只给前后指标、固定诊断投影、原理由与检查结论；剥离源码、完整身份引用及私有路径，不把评价源码或已有成功后代答案放进更新包。

选择依据与依赖关系见[方法说明](../analysis/2026-10-20-policy-method-rationale.md)和[状态盘点](../analysis/2026-10-20-repair-state-inventory.json)。**这些数据都已被研究者看过**，不同源码也不代表独立任务。规划继续使用Spanner的2个提示题与8个开发题，符号继续使用oscillator1的10,000行train观测；没有执行oscillator2或封存测试。官方来源仍是llm-genplan与LLM-SR原论文公开数据，详见[数据说明](task-data.md)，并非LLM-SRBench。

## 3. 为什么设置三个条件

| 条件 | 修订策略 | 是否直接看到两张经验卡 | 要区分的问题 |
|---|---|---|---|
| fixed | S0 | 否 | 固定策略本身会产生什么结果 |
| memory | S0 | 是 | 直接提供经验记忆是否已有帮助 |
| updated | S1 | 否 | 将经验压缩为规则选择与顺序，能否产生不同修订 |

2个评价状态×3条件×2次抽样，共12个单步会话，另有1次策略更新请求。每组三个条件从同一源码、诊断、任务说明和证据目录开始；仅策略与经验记忆两个通道允许变化。全部组都能看到8条规则目录，因此比较的是强调哪些规则及其顺序。第二次抽样反转执行次序，每会话只给一次请求和至多一个候选；没有补齐失败提交。

S1在评价前单独保存和冻结；评价不再改S。两次抽样共用这一次更新，不等于重复学习两次。运行前验证共同状态，运行后又从SDK发送前保存的请求核对4组三方共同内容；没有另行捕获原始HTTP报文。输入更长的memory和额外付出更新成本的updated，不能称为同token预算。

## 4. 实际结果及最值得看的一处源码

| 状态／抽样 | fixed | memory | updated |
|---|---:|---:|---:|
| 规划／1 | 0/10 | 无候选，质量留空 | 10/10 |
| 规划／2 | 0/10 | 0/10 | 0/10 |
| 符号／1，train NMSE | 0.09576767 | 0.09576767 | 0.09414522 |
| 符号／2，train NMSE | 0.09588310 | 0.09576767 | 0.09414522 |

规划新策略第一次采用完整状态BFS，正确枚举携带的多个可用工具，[程序](../../artifacts/policy-transfer/2026-10-20/v01/EP-r1-updated/candidates/planning-001.py)通过10题；第二次又采用逐个取工具的有向贪心程序，到末端后无法回取，仍0/10。固定组另有缺少函数实参的TypeError；记忆组一次把多个携带工具压成单值，返回空计划。这说明需要检查规则是否落实为正确的状态表示和编辑，不能只看理由是否说得合理。

符号新策略两次都选择`a*x+b*v+c+d*v*abs(v)`，相对父公式NMSE下降约0.001772；fixed/memory主要选择`v²`项，下降更少。两份新策略源码只改变自由系数的符号，代表同一函数集合，不能记成两种新公式。`v*abs(v)`为奇函数，但系数未限制符号，不能据形式认定物理耗散机制，也没有证明发现真实方程。

缺失的规划记忆组确有工具调用，只是理由2016字符超过2000上限16字符，工具契约拒绝后未执行；它不是0分程序。11个实际候选产生50次规划执行和6次符号拟合；66条复制的旧基线记录不计入新执行。11项主张只有1项受支持，另有5项数值矛盾、4项类型/算子错误和1项不存在的引用ID；11项预测中2项达到阈值。有效提交、主张正确、预测达标、产物改善是四个不同指标。

完整源码解释、理由误读及逐项数值见[分析报告](../analysis/2026-10-20-policy-transfer-analysis.md)。本轮训练/开发结果不能写成测试集准确率、普适改进、统计显著或GEPA/ExpeL复现。

## 6. 验证、成本与下一步

实跑前380项不同测试通过；事后新增14项审计测试通过，13种破坏副本均被拒绝。231份新原始文件与服务器一致，旧原始文件保持不变；离线审查没有新增模型调用或候选执行。

本轮120,007 tokens，按配置单价估算约**0.3674元**，保守预留1.4669元；usage全部已知，金额不是供应商账单。其中更新S约0.0191元，fixed评价0.1110元、memory评价0.1346元、updated评价0.1026元；updated加学习成本约0.1218元。历史一次未知usage仍保留，不据本轮数字填补项目历史总账。

下一步应优先把已观察的误读变成更准确的更新机制：区分事实与解释、核对诊断是否对应当前父产物、把所选规则绑定到具体源码修改、在预测反证后重新审查规则。随后在按轨迹和公式族去重、事先分离的更多状态上验证，并重复策略更新本身。本轮已迈出真实更新S的一步，尚未让更新器自我改写，也没有完成可靠泛化验证。
