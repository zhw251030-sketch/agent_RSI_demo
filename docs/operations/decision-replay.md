# 冻结证据回放：从临时检查到最终修订

本工作单元承接[two-stage](two-stage.md)，解决“检查时临时修改”和“最后提交修改”被混淆的问题。最新运行结果、逐例判断及费用见[本轮分析](../analysis/2026-10-21-decision-replay-results.md)；约束以调用前提交的[协议](../protocols/2026-10-21-decision-replay-v0.1.md)为准。

## 为什么需要这一轮

上一轮两个符号self会话把“登记删除一项进行检查”理解成最终需要提交删项式，导致退化；checked看到删项损失后保留原项。这并不足以说明反馈机制优于合理的普通修订，因为对照可能受到了编辑暗示。另一个checked候选多加了x⁵，误差仅下降3.419e-10，却增加一个参数；纯数值下降不应自动成为有意义的成果。

这次双方都明确允许原样保留，完全去掉旧登记、planned_edit及父公式源码，同时加入相反方向的案例。如果检查结果能帮助决策，应该既能保留有用项，也能识别低收益项可简化；不能只看“少犯错”，更不能用一律不改获得表面优势。

本轮不是新的完整两阶段Agent，也没有学习持久策略S。它把已验证的检查结果作为固定输入，单独研究“观察→修订决定→实际评价”这段联系。重复仍来自相同的开发数据，只有生成过程是新请求。

|---|---|---|

| [配置](../../configs/pilots/decision-replay-v0.1.json) | 固定请求、tokens、费用与96次sandbox上限 | 发送和执行前就约束预算 |
| [案例装载](../../rsi_eval/decision_cases.py) | 校验27个原文件，装载当前产物和检查白名单投影 | 使用真实来源，防止泄漏完整干预程序、拟合参数或推荐动作 |
| [决策与评分](../../rsi_eval/decision_core.py) | 原样/自由修改均可提交一次；区分数值收益、实用收益、简化和退化 | 让保留决定合法，也防止把微小数值波动夸大为进步 |
| [OpenHands适配](../../rsi_eval/decision_agent.py) | 新共同系统提示；仅submit_candidate/finish；一个请求 | 避免隐藏终端、文件与额外调用造成信息或预算差异 |
| [运行器](../../scripts/run_decision_replay.py) | 冻结代码与输入，交错两个条件，记账后执行，保存实际请求 | 同一案例四个请求删除唯一feedback字段后必须一致 |
| [只读审计](../../scripts/analyze_decision_replay.py) | 从原记录重建来源、输入、源码提交、计分与逐事件计数 | 不凭模型自述判断成功，不用汇总数字替代原证据 |

旧运行模块、旧候选和历史分数均保留原样。本轮新增模块避免让事后实现影响旧轮可复核性。

## 四个状态代表什么

P-format是一个已生成完整动作序列、却因括号边缘空格而无法通过验证的规划程序。已归档检查证明，在两个公开实例中仅清理该空白足够；模型仍需自己决定并提交源码，不能直接得到检查后的计划或人工补丁。

P-empty生成空计划。对空计划清理空格不能完成任务，所以该检查不足以支持“格式修一下就好”。这检查的是充分性，不是说程序没有任何其他错误。

S-v3是含v³加项的已有公式；原检查将该项删除并重拟合，训练NMSE增加约0.0015133，超过1e-5。S-x5是另一已有公式，其x⁵删除损失约7.1802e-7，低于1e-5：在本轮约定的误差与参数数取舍下，可以考虑简化。这些判断仅绑定既定训练数据、拟合初值和迭代上限，不能解释为物理项必要性或测试集效果。

源码注释逐字节保留，S-v3注释包含约0.0938的旧父式分数，两组都能读到；因此hidden并非毫无相关先验。两组同时省略历史诊断表和父代码，保留当前分数与公开接口。信息改动已在协议中披露。

## 一次会话如何运行

```mermaid
flowchart LR
    A[固定的历史产物与任务接口] --> B[共同决策提示]
    E[已归档检查观测] --> C[checked可见 / hidden为null]
    C --> B
    B --> D[一个OpenHands模型请求]
    D --> F[提交完整源码：原样或修改]
    F --> G[可信执行器隔离运行]
    G --> H[分数、编辑类型、用量和原始证据]
```

两次重复没有共享会话记忆；第二次也不能看第一次答案。反馈来自预先已完成的检查，新增probe调用为0。原样源码也通过同一执行器重新评价，不能直接搬历史分数当本轮结果。规划执行10个开发用途实例，报告8个development与2个公开实例；符号每个候选进行一次fit、一次独立predict。

## 怎样避免误判

符号实用收益需要NMSE下降超过1e-5；少参数且损失小于1e-5则另记可接受简化；边界±1e-10不强行判定。额外参数没有带来上述实用收益会单列。参数数只是复杂度代理，不能证明程序更简单，也不能证明模型解释有依据。精确编辑类别来自源码/窄AST比较，预测字段错误单独报告。

运行前修复了三处新流程边界：模型用量未知时阻止候选执行；执行阶段缺失/错序不能计作成功；每个执行账目必须绑定自己的评价记录，不能只核对合计。真实SDK模拟调用验证了合法工具响应但usage缺失时，新增候选评价为0。

审计是保存记录与源码的一致性检查，不是重新调用VAL或从原始预测数组独立重算NMSE，也不能认证完全自洽的伪造历史。结果只支持本轮开发观察，不能直接写成“普适RSI方法已验证”。
