# 从冻结起点到策略选择：接口准备

本轮把三处缺口接起来：哪些任务允许在什么阶段执行、模型究竟从哪些旧经历学习、真实终稿成绩如何进入策略选择器。它是后续36请求实验的接口准备；本轮没有发模型请求、执行八份冻结起点、产生S1或证明RSI收益。

## 文件怎样配合

| 文件 | 做了什么 | 为什么需要 |
|---|---|---|
| [角色执行器](../../rsi_eval/role_executor.py) | 学习、选择、评价分别检查任务ID和数据哈希；候选只在原沙箱运行 | 原执行器只允许开发任务，不能通过改旧权限伪装新评价 |
| [学习材料与提示构建](../../rsi_eval/strategy_learning.py) | 校验两批旧归档，保留全部24终稿和来源，渲染更新/修订输入 | 防止只挑正例、遗漏反例或把新评价诊断喂给策略 |
| [更新提示](../../prompts/strategy-pair/update.md)、[修订提示](../../prompts/strategy-pair/actor.md) | 固定学习目标和修订目标，只有选中的四条规则进入actor | 策略内容与更新理由分离，使比较对象明确 |
| [实测记录绑定](../../rsi_eval/strategy_binding.py) | 核对请求、共同上下文、源码、数据与执行收据，分别调用两次策略选择 | 单纯填写成功数或相同哈希不等于有对应执行证据 |
| [准备入口](../../scripts/prepare_strategy_pair.py) | 重审八份来源、角色元数据，冻结学习包与运行文件 | 留下真正可复查的输入清单，不制造尚不存在的成绩 |
| [本轮协议](../protocols/2026-10-21-strategy-interface-v0.1.md) | 明确阶段顺序、反馈权限和验收范围 | 避免获得评价成绩后再改变机制或选择规则 |

## 学习材料到底是什么

采用 decision-replay 的16份与 edit-commitment 的8份历史终稿，共24份。底层仍只有四个已见状态，任务仅Spanner seed0十题与oscillator1/train；这不是24个独立任务，也不是全项目所有历史材料。

保留全部案例、完整不同源码、每题结果、公开规划/训练残差诊断、原始决策与编辑声明、检查和probe观察。重复源码和测量表按哈希去重；自由说明、重复元数据和过程轨迹留在归档中。投影规则对所有案例相同，没有按收益删例或截断文字。旧源码及其注释是待分析数据，不能作为新的执行指令。

新起点静态分析、oscillator2和评价方程的新反馈均不在学习包里。学习仍改变原8条规则中的4条有序选择；这是固定模型权重下的有限外部策略更新，并非完整GEPA复现或更新器自改写。旧接受标签也不证明某条规则已经有效。

## 两道权限分别控制什么

任务角色决定数据范围：学习10个规划题/oscillator1，选择19个规划题/oscillator2，评价63个规划题/bactgrow和stressstrain。所有官方测试继续封存。

起点阶段决定什么时候允许运行：评价起点即便只是去学习题获取反馈，也必须等两个S*都冻结。后续调度器必须调用起点阶段守卫，再调用任务执行器；单靠task role无法识别“评价源码在学习题上运行”。

规划actor只看原seed0上的反馈；19/63题的成绩由宿主评分，不回传同次修订。符号actor可看当阶段train拟合反馈，但train分数始终不是独立预测成绩。

## 为什么要有两个策略选择结果

未来r1/r2各自从S0和同一学习包提一个S1，分别在四个选择状态上比较固定/更新终稿。每次调用接受器只包含该重复对应的策略，不能把不同S1混在一个对象里，也不能挑其中表现更好的重复作为最终结果。

两个完整选择结果冻结后才开放评价。若某次S1被拒，则该次S*=S0；之后同策略两次随机调用的差异不能被解释成策略更新收益。缺失或不确定不记零分，也不允许靠补抽补成一轮成功实验。

## 验证与下一步

本轮使用边界负例和临时人工任务验收接口。合成校准使用手写规划程序、线性/常数公式和人工PDDL/CSV，在服务器真实沙箱及VAL中执行；它只验证工具链，绝不算Spanner或符号发现成绩。最终测试、准备包哈希和校准记录见本轮验收文件。

准备命令在干净提交后执行：

```bash
.venv/bin/python scripts/prepare_strategy_pair.py --output runs/strategy-interface/prepare-v01
.venv/bin/python scripts/prepare_strategy_pair.py --output runs/strategy-interface/prepare-v01 --verify
```

下一步是独立的有界SDK调度器：消费新版学习包，核对真实发送请求与SDK提交，运行学习/选择并冻结两个S*，再开放评价。正式调用前必须完成完整36槽假provider集成和实际请求字节上限检查。当前 `execution_ready:false` 明确保留；源码已齐全、接口可验证，与完整模型实验已能启动是不同状态。
