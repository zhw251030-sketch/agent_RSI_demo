# 编辑声明一致性检查：本轮做了什么，为什么这样做

本轮完成了零模型、零候选执行的离线检查：把上一轮全部16份真实提交的原文声明、提交源码、执行环境和历史成绩对在一起。结果是14条人工抽取的窄编辑谓词得到支持、2条未知；另6条明确的逐字保持声明中5支持、1矛盾。这些数字不是Agent成功率，也不是解释正确率。

## 为什么现在做这个

上一轮P-format中，一份提交看到“清理动作字符串后可以通过”的诊断反馈，却保留原代码，认为最终host会自动完成清理。另一次提交真正修改了格式输出，历史评价通过10/10。于是需要辨别三个问题：模型决定保留还是修改；实际提交是否落实这一决定；执行环境是否真的包含模型依赖的处理步骤。

如果把这三件事混为一个“反思正确”分数，策略学习可能吸收错误经验。例如第一份keep声明实际上为真，不能把它标为“声称修改却没修改”；它的问题是部署假设错误，而且保留没有改善任务。本轮先把可检查事实做清楚，后续更新策略时才有明确的反馈对象。

## 四种检查如何工作

`keep_bytes`要求源码字节与参数元数据保持一致；`keep_ast`允许普通注释和空白变化，但要求投影后的整棵语法树与参数元数据相同。AST可以理解为把程序语句及其结构解析出来的树，因此末尾换行不算算法改变。该投影不是任意程序的语义等价证明；包括type-ignore附着位置等边界在协议中明示。

`apply_format_patch`要求候选整树等于已有受限格式变换产生的整树，不能只检查“出现了strip”或只看某个辅助函数名称。原样提交、顺便改变目标判断、插入副作用或增加另一个格式函数，均不能冒充限定格式修复。这个检查不证明修复后的程序一定被调用或解出任务。

`remove_selected_term`绑定原式、具体参数项和已核验父式，要求参数正确减少、导入与函数外围不变，候选完整AST等于绑定父式。它不会把“x**5不再出现在文本中”或“系数置零”直接认作正确删项。对于更广的等价公式改写或新程序结构返回未知；这也不证明删除具有物理依据。

在服务器项目目录内可复核：


本轮新增模型请求、token、模型费用、候选执行、probe执行、策略更新和权重更新均为0。项目累计研究请求仍103次，已知820401 tokens、估算2.5144056元、保守预留10.7783256元；最早一笔usage未知仍保留，不含连接调试、Canvas及其他项目消费。

## 对RSI机制研究的作用和下一步

本轮提供了一个可以接入策略更新的检查组件，没有完成新一轮策略学习。后续可将“当前证据支持什么—准备做哪类编辑—实际做了什么—产生了什么效果”分开保存，避免把诊断副本的成功、口头解释或格式合规当作策略有效的经验。

下一轮应前置结构化编辑承诺，以相同模型和请求预算比较普通修订与收到窄检查反馈的修订；同时把部署假设检查与源码编辑检查作为可分辨组件。策略学习/选择状态与评价状态须事先分开，不能继续从这四个已见状态抽样后宣称泛化。未知不能一律当作错误或禁止新算法：检查器能力之外的改写应保留未知，再由独立执行结果评价其作用。
