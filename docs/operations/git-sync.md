# GitHub 与服务器同步约定

日期：2026-10-20。仓库：`zhw251030-sketch/agent_RSI_demo`，要求保持 **Private**；默认分支 `main`。

## 同步内容

保存研究设计、来源清单、状态、代码、配置模板、任务划分、评价协议及可公开给仓库成员的实验摘要。初次导入的 12 份研究稿是带校验的历史快照，后续工作以本仓库为项目入口，不自动扫描或上传上级文献库。

不提交凭据、私钥、个人材料、服务器连接信息、受限数据、虚拟环境、模型和原始运行目录。大文件仅登记来源、版本、校验和获取方式；不能用忽略原始日志的方式丢弃唯一实验记录，原件须另行持久保存。

## 每次工作

1. 开始前检查 `git status --short`，获取远端状态，在工作树干净且分支允许快进时执行 `git pull --ff-only`。
2. 完成一个可审查工作单元后更新相关状态，检查 diff、敏感信息和新增文件；按明确路径暂存，不盲目提交整个上级目录。
3. 创建描述具体变更的 commit，运行相应检查后 `git push origin main`。
4. 对比本地 HEAD 与 `git ls-remote origin refs/heads/main`；服务器同步后再次核对 HEAD、工作树与文件校验。
5. 同步失败就记录失败原因和待推送提交，不称为已同步；出现分叉或未提交修改时先审查并整合，不强制覆盖。

## 服务器传输

本机已有 GitHub SSH 身份。服务器在 2026-10-20 的检查中未通过 GitHub 主机密钥校验，因此尚未证明能直接拉取/推送。当前采用本机作为同步桥梁，以既有服务器 SSH 通道传输 **Git bundle**，在服务器快进到同一提交；不复制 GitHub 私钥。

从本机发送新提交：本机创建 `git bundle create <bundle> main`，经 SSH/SCP 传输；服务器在工作树干净后从 bundle fetch，再 `git merge --ff-only <fetched-commit>`。已有目录不得被 clone 或 reset 强行覆盖。

服务器产生提交后：服务器创建包含分支的 bundle，经 SSH/SCP 回传；本机 fetch 到临时审查分支，检查并快进/整合后 push GitHub。随后核对三处提交。连接别名和实际路径仅保存在本地管理记录中。

这是一项随项目工作执行的同步约定，不是后台定时任务，也不是环境、大数据或凭据的完整备份。
