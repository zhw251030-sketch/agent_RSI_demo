# 固定权重 RSI：改进机制比较与研究建议 v0.1

日期：2026-10-15。性质：定向文献研究与项目讨论稿，未实施、未调用实验模型、未得到本项目实验结果。发表身份与阅读范围截至本轮检索；正式发表不等于结论已经独立复现。

## 1. 当前要求与结论

用户最新明确的顺序是：**基础模型权重固定，先深入研究改进及其机制，再检验机制能否用于多类任务。** 跨任务适用性是后续证据，不能提前成为组织全部项目的主轴。原工具调用与重规划方案仍是历史候选，BFCL、黑盒解释或任一具体基准均未重新锁定。

本轮重点比较三组共 23 项方法，另补充 AgentOptimizer、Agent-Pro、EvoTool，共 26 项固定权重方法；同时核查近期近邻、反面证据和公开评测入口。各篇阅读深度不同，见补充文件。本轮是问题驱动的范围检索，不能称为穷尽的系统综述。

综合建议：**先用 GEPA 一类边界清楚的更新框架，研究反馈如何影响修改质量，以及选择过程如何保留或掩盖这些修改。** Trace 提供计算图与轨迹干预参照；若需要改控制流程，再考虑 AFlow；若进一步让更新器自身参与学习，再进入 Promptbreeder / STOP。这是研究起点建议，尚未确定最终方法、新颖贡献或实现任务。

## 2. “研究改进机制”有两种含义，不应混在一起

令固定模型为 Mθ，可持久改变的 Agent 状态为 S：提示、经验、工具函数或工作流。一次更新可以写成：

`任务执行 → 轨迹和反馈 F → 提出候选 S′ → 评价与选择 → 下一轮状态 S`

研究者可以改变反馈组织、提案方法或选择规则，研究它们如何影响更新。这已经是在研究和改进机制。只有进一步让系统根据经历修改更新器 U，才进入“更新器也自我改进”的更强设定；当前用户没有要求第一阶段必须做到后者。

| 层次 | 实际改变什么 | 应当测量什么 |
|---|---|---|
| 当前问题的修正 | 当前答案、当前计划、当前轨迹 | 本次任务是否改好，是否只是获得更多尝试 |
| 可复用 Agent 的更新 | 通用提示、经验、技能或工作流 | 在独立任务实例上，更新是否产生持续收益或退化 |
| 更新器的更新 | 生成修改的提示、操作选择策略或程序 | 固定任务 Agent 起点和资源后，新更新器是否更善于产生有效修改 |

单次修正可为后两层提供经验，但其成功不自动证明长期学习。SCoRe 等改变权重的方法不作为当前主方法；“不能内在自纠错”的特定实验也不能推成所有外部反馈学习都无效。[ICLR 2025 SCoRe](https://proceedings.iclr.cc/paper_files/paper/2025/hash/871ac99fdc5282d0301934d23945ebaa-Abstract-Conference.html)，[ICLR 2024 自纠错研究](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)。

## 3. 最值得优先比较的机制

下表只给阅读与选型用途；具体机制、任务、来源和限制分别保存在三份补充文件，避免把不同论文的裸分数横向排名。

| 机制路线 | 主要论文与正式状态 | 对本项目最重要的问题 | 当前取舍 |
|---|---|---|---|
| 轨迹反馈驱动提示更新 | GEPA，ICLR 2026；ProTeGi，EMNLP 2023；OPRO，ICLR 2024 | 收到什么反馈，怎样变成修改，哪些候选被继续探索 | GEPA 优先作可拆解的研究底座；OPRO 提供仅分数历史的对照思路 |
| 计算图上的反馈归因 | Trace，NeurIPS 2024；TextGrad，Nature 2025 | 末端评价怎样传到具体可修改变量，轨迹信息是否被正确利用 | Trace 优先补读；语言“梯度”不提供数值梯度的理论保证 |
| 多模块提示与示例搜索 | MIPRO，EMNLP 2024；EvoPrompt，ICLR 2024 | 提案好还是搜索好，示例与指令各贡献什么 | 用作强近邻与必要对照，避免把所有收益归给反思 |
| 工作流和程序更新 | AFlow、ADAS、AgentSquare，ICLR 2025 | 怎样选择修改位置、控制修改范围、利用历史 | 如研究对象是规划控制流程，AFlow 比同时开放全程序更便于归因 |
| 经验及记忆更新 | ExpeL，AAAI 2024；CER，ACL 2025；ACE / ReasoningBank，ICLR 2026 | 从失败中学到的是正确规则还是错误概括，何时影响后续行为 | 与长期研究主线紧密，但先控制经验内容与使用条件，避免一次叠加整套记忆系统 |
| 更新器自身演化 | Promptbreeder，ICML 2024；STOP，COLM 2024 | 如何证明“更会改”，而不仅是当前成品更好 | 第一阶段的评价参照与后续扩展，非必须实现的前置目标 |

完整来源与证据：[补充 A：提示与计算图优化](补充A_提示与计算图优化.md)、[补充 B：程序与改进器演化](补充B_程序与改进器演化.md)、[补充 C：经验记忆与技能更新](补充C_经验记忆与技能更新.md)。

这组文献不是同一种通用算法的不同名字。其可修改表示、反馈条件和评价代价明显不同。方法来自成熟会议可以提供可信参照；实际适合我们的依据仍是：修改对象清楚、反馈能被干预、结果能独立检查、基线能公平比较。

## 4. 本轮另外找到的三个直接相关方法

| 方法 | 做了什么、用什么任务 | 对本项目的价值与边界 |
|---|---|---|
| **AgentOptimizer，ICML 2024**；正式标题 *Offline Training of Language Model Agents with Functions as Learnable Weights* | 固定 LLM，增删改可调用函数库，利用执行历史和训练成绩更新；包含回退、早停。任务为 MATH、TabMWP、GAIA | 可执行函数比整段反思更易检查；论文已经讨论训练提升而测试下降，也有 MATH 子领域迁移。不能把回退、函数积累或早停本身作为新贡献。[正式记录](https://proceedings.mlr.press/v235/zhang24cd.html)，正文 §2–3 |
| **Agent-Pro，ACL 2024** | 通过策略反思、搜索更新文字化决策策略；Blackjack 和 Limit Texas Hold’em | 证明固定权重下的策略改进可放在序贯决策环境研究；两个牌类环境不能证明广泛跨域。此处仅将其作为机制邻近工作。[正式全文](https://aclanthology.org/2024.acl-long.292.pdf)，方法及附录评测 |
| **EvoTool，ACL 2026** | 固定规划、选择、调用、综合四类模块结构；轨迹归因后定向修改一个模块，再进行种群选择。ToolBench、RestBench、τ-bench、BFCL | 与“找错因再改规划提示”非常接近；已有轨迹／反馈消融和选择对照。ToolBench ↔ RestBench 是演化后策略的迁移。其错误归因由 LLM 诊断，不能直接视为真实因果标签。[正式全文](https://aclanthology.org/2026.acl-long.2016.pdf)，§3–7 |

AgentOptimizer 曾以 *Training Language Model Agents without Modifying Language Models* 为预印本标题；正式引用采用 ICML 标题。EvoTool 的发表身份可由 [ACL 页面](https://aclanthology.org/2026.acl-long.2016/)确认。本轮没有运行这些项目的官方实现。

## 5. 推荐先回答的一个问题

**在相同起点、相同经历和相同资源下，反馈驱动的更新为何有时有效、有时退化？差异发生在反馈解释、修改提案，还是候选选择？**

这是一项尚待收窄的机制问题，不是已确立的新方法名称。第一阶段仍需要一类真实公开任务承载观察，但不要求同时覆盖多类任务。

建议从一个可修改对象开始，例如 Agent 中某个可复用决策模块的提示；保持执行器、工具接口和评分标准固定。若观察到问题实际来自流程表达能力，再有理由转向工作流代码。不要同时开放提示、经验库、工具库、检索和控制流，否则难以定位改进来源。

### 5.1 先把修改质量与挑选效果分开

以下是本项目的实验设计建议，不是已有验证结果。

1. **固定起点。** 保存一组父 Agent 状态和它们产生的轨迹。不同更新方法从相同起点出发；不能让一组主要修改较弱父状态，另一组修改已接近饱和的状态。
2. **干预反馈到修改的环节。** 在相同信息权限下，比较原始轨迹、分数历史、文本诊断等组织方式；额外真值反馈必须单列条件。保留全部修改，包括无效、未采用和导致退化的修改。
3. **独立测提案。** 在不反馈给更新器的审计样本上测量修改前后表现差值，关注平均增益、退化、原有成功任务丢失及修改类型。有限样本只给估计与不确定性，不能把一次正差值称为真实有效更新。
4. **固定候选测选择。** 对共同候选池比较选择规则，检查被选者相对父代及候选池表现；这样能区分“提出了更好的修改”和“更会识别修改”。用于研究选择误差的审计结果不能再回流调参或挑最终赢家。
5. **恢复完整循环。** 单步机制成立后，检查连续更新是否累积收益，或在后期因错误经验、评价适配和选择偏差而退化。

独立重复应包括整个改进过程的重复。不同任务实例、同一候选的多次调用、不同优化运行是不同层次，不能把它们合在一起当大量独立样本；必要时按任务来源／模板和运行分组分析。

### 5.2 如果进一步研究“更新器也变好”

设固定更新器为 U0，经过经历得到 U1。先冻结两者，在新的父 Agent 状态和反馈案例上比较其产生修改的质量，保持候选数、信息和资源一致；这一步可以仍在同一任务族中完成。随后再测试第二类任务。

Promptbreeder 已经演化 mutation prompt；STOP 已将改进器自身作为被优化程序。因此，“让模型修改改进提示”不是新颖性。需要进一步确定一个失败现象和相对成熟方法的实质差异。[Promptbreeder](https://proceedings.mlr.press/v235/fernando24a.html)，[STOP](https://arxiv.org/pdf/2310.02304)。

## 6. 哪些想法已经有直接近邻

| 看似自然的想法 | 已有覆盖 | 对我们的限制 |
|---|---|---|
| 根据轨迹先判断错在哪，再改相应模块 | EvoTool；CHIME 预印本 | 单纯增加归因环节不足以声称新方法 |
| 研究反馈噪声会不会污染学习 | ReasoningBank 正式版已有随机翻转成功标签实验 | 需明确是何种噪声或语义错误，以及为何现有机制处理不好 |
| 不重写全部经验，只增量维护 | ACE | 条目化、去重、局部修订不能单独构成贡献 |
| 保留多样候选，避免总从当前最好者出发 | GEPA、EvoTool、DGM | 若研究选择，应针对更具体的错误接受或淘汰机制 |
| 让修改提示／改进器代码自行变化 | Promptbreeder、STOP，另有 HyperAgents 预印本 | 要测更新能力本身；成品分数上涨不足以证明它 |
| 轨迹信息是否有用 | Trace 已做相关干预 | 仅移除轨迹做消融还不足以形成新认识 |

来源见补充 A–C 与 [EvoTool](https://aclanthology.org/2026.acl-long.2016.pdf)、[CHIME](https://arxiv.org/html/2609.02074)。CHIME 将规划、执行经验分库并按归因更新；其结论来自作者的四基准实验，本轮未核实正式会议录用。

还需关注两类近期反面证据。其一，[On the Fragility of Self-Improving Agents](https://arxiv.org/html/2608.18066v2)在特定 AWM／ReasoningBank 设置下报告运行方差、任务顺序和环境说明不足影响收益，不能泛化为全部方法无效。其二，[深度研究 Agent 的反思提示优化研究](https://arxiv.org/html/2610.12601)检查了主题隔离、多随机种子和反馈形式；其评价主要依赖 LLM judge，人工核验较小，不能将它的选择偏差解释当成普遍定理。两篇截至本轮均按预印本使用。

这些近邻提高了研究问题的精度要求，没有消除研究价值。可能有价值的贡献是：识别可重复的具体失效条件，提出针对性修改，并解释它在何种条件下起作用。当前尚未验证这样的失效条件。

## 7. 任务的权威性与后续适用性验证

公开任务既要有可信来源，也要能暴露研究机制。这里的任务是候选测量环境，尚未选定。

| 研究需要 | 可参考的公开环境与出处 | 优势及边界 |
|---|---|---|
| 可执行代码的修改、明确反馈 | AFlow 使用的 HumanEval、MBPP | 测试便于复查修改影响；通过有限测试不能保证程序正确，且代码能力不等于一般 Agent 规划 |
| 数学／多跳推理的提示或流程更新 | GEPA、AFlow、ADAS 所用 MATH、HotpotQA、DROP 等 | 有成熟比较链，便于控制起点；只看答案正确率可能隐藏机制差异 |
| 多步行动、状态和前提条件 | ALFWorld；AgentBoard 中的规划／交互环境 | 可观察动作和状态变化；具体环境依赖、评分与可见信息仍需部署前核查 |
| 多工具、应用状态、连锁影响 | AppWorld，ACL 2024 | 模拟应用和状态检查适合研究修改是否损坏其他行为；环境较复杂，不宜先用规模取代问题定义 |
| 工具调用与用户交互 | BFCL，ICML 2025；τ-bench，ICLR 2025 | 有标准评价，适合结构／状态约束；BFCL 各子集性质不同，不能泛称都测规划 |
| 后续多类任务的共同入口 | AgentBoard，NeurIPS 2024 Datasets & Benchmarks；AgentBench，ICLR 2024 | 提供多环境评测组织方式；统一接口不消除每域反馈和任务难度差异 |

评测原始来源：[AgentBoard](https://proceedings.neurips.cc/paper_files/paper/2024/hash/877b40688e330a0e2a3fc24084208dfa-Abstract-Datasets_and_Benchmarks_Track.html)、[AgentBench](https://proceedings.iclr.cc/paper_files/paper/2024/hash/e9df36b21ff4ee211a8b71ee8b7e9f57-Abstract-Conference.html)、[AppWorld](https://aclanthology.org/2024.acl-long.850/)、[ALFWorld](https://alfworld.github.io/)、[BFCL](https://proceedings.mlr.press/v267/patil25a.html)、[τ-bench](https://proceedings.iclr.cc/paper_files/paper/2025/hash/1b126cc38b8638e07bef37e7b2bb72bf-Abstract-Conference.html)。方法使用哪些任务的逐项证据见补充 A–C。

后续“适用于多类任务”至少有三个不同主张：

- **算法复用**：同一更新机制分别在不同任务上运行，各自学习。
- **产物迁移**：在任务 A 得到的提示、技能或 Agent 直接用于任务 B。
- **改进能力迁移**：在 A 获得的更新器，能在 B 中更有效地产生修改。

多数多基准论文主要支持第一种，部分支持第二种。第三种最接近更强的 RSI，但不能由前两种推出。当前第一阶段没有必要承诺第三种。

## 8. 下一步的实际顺序

1. **先精确拆解 GEPA 与 Trace。** 对照它们的可修改对象、反馈接口、提案与选择过程，找出仍需观察的具体问题；GEPA 已有本地阅读积累，Trace 可补足机制干预视角。
2. **按更新对象选一条分支。** 若关心流程修改，补 AFlow；若关心更新器学习，补 Promptbreeder 与 STOP；若关心经验误用，补 ReasoningBank／ACE，并对照 EvoTool、CHIME 等近邻。
3. **选一类成熟任务承载初步观察。** 要求反馈能检查、失败可重复、更新日志可审计。先观察瓶颈，再决定针对性的机制变化。
4. **机制获得证据后再扩展任务。** 固定核心更新原则，仅增加必要的任务适配器，并报告哪些部分必须改变、哪里失效。

本轮没有确定最终论文贡献，没有证明新机制有效，也没有产生可以写为“已完成实验成果”的简历条目。模型与价格仍按用户要求后置。
