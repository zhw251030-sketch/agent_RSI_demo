# 形式规划与符号发现：联合研究设计 v0.1

日期：2026-10-17。性质：用户已选择两条研究路线；本稿提出共同问题与实验结构，具体机制、任务子集和实验参数尚未冻结。未安装或运行环境、未调用实验模型、没有新实验结果。

## 1. 已确认的选择与本轮建议

用户明确计划同时推进**形式规划与符号发现**。这取代此前“形式规划／算法发现优先比较”的助理推荐。两条都进入当前项目，不再要求用户二选一；在线装箱、TSP、ALFWorld 等保留历史背景。

基础 LLM 权重固定；先深入研究改进机制，再检验同一机制在不同任务上的适用性。模型与定价继续后置。用户尚未确认下文具体子集、GEPA 适配或任何新机制；本稿不得用作“方法已选定或验证”的证明。

建议把两条组织为**一个机制问题、两个评价环境**：

> 系统怎样利用有限的执行证据修订解决问题的策略，获得在新状态或新问题上仍有用的改进，同时避免将局部有效的改动概括成错误经验？

这是一项候选研究问题，不是已确认的文献空缺。两条路线共同研究反馈到策略更新的环节，各自保留有实质意义的任务目标。

## 2. 两条路线分别承担什么

| 维度 | 形式规划 | 符号发现：首版具体化为符号回归 |
|---|---|---|
| 输入 | PDDL 动作规则、对象、初始状态和目标；供开发的规划实例 | 问题描述、变量和数值观测；允许的公式表示与算子 |
| 产物 P | 能为同域新实例产生合法计划的 Python 程序 | 可执行的公式或公式程序；常数可数值拟合 |
| 可见执行证据 | 异常、首个非法动作及缺失前提、未达目标、超时 | 执行异常、非有限值、拟合误差、从可见数据计算的残差模式 |
| 成品评价 | 独立实例的成功覆盖、失败类型、有效计划代价 | 留出观测的误差、结构恢复、复杂度及适用的分布外评价 |
| 主要机制观察价值 | 具体失败相对易定位，可检查修复是否损坏已成功行为 | 低误差不唯一确定正确结构，可检查错误概括与过拟合 |

两种反馈有不同强度。计划验证器判断一个具体计划是否合法，不证明整个规划程序对任意实例正确。符号回归的观测一致性更不等于真实公式或因果规律；基准真值公式只用于评估，不提供给更新器。

**共同更新对象建议是显式的“修订策略” S。** 它规定遇到某类执行证据时怎样诊断、提出候选和检查修改。P 与 S 分开保存：修改一个公式属于产物搜索；改善后续公式构造的指导，才是策略更新的候选证据。这里的 S 不强制是巨大经验库，也不要求第一版同时开放工具库、检索器和控制流程。

共同结构可写为：

`当前产物 P、策略 S → 固定模型提出候选 → 任务执行器返回证据 → 更新策略 S → 用新策略继续修订 P`

两边共用策略的表示、更新与选择规则，任务适配器负责输入输出、执行和评分。允许学到不同的策略内容；首先检验同一算法分别在两类任务中是否有效。把规划经验直接迁到符号发现、或让更新器自动重写自己，属于更强的后续主张。

## 3. 具体方法与任务配套

### 3.1 形式规划入口

建议首版采用 **llm-genplan 的完整规划程序**，先选官方 PG3 变体中的 Spanner，再用 Miconic、Ferry 检查同族推广。该方法在 [AAAI 2024 正式论文](https://ojs.aaai.org/index.php/AAAI/article/view/30006)中已使用固定 LLM 生成、调试通用规划程序，源码与原始训练／测试任务见 [官方仓库](https://github.com/tomsilver/llm-genplan)。原设置和已读代码入口详见 [补充 E](../rsi-mechanism-review-2026-10-15/补充E_形式规划与可复用规划程序.md)。

选择完整规划程序，是为了同时观察语义错误、修复和成功能力损失；它与公式程序修订的共同对象更直接。这是针对联合项目的取舍，不是断言它比启发式路线更好。固定搜索器、只修改 `h(state)` 的 IPC 方案仍可保留为规划侧扩展，但不在首版同时建设两种规划接口。

同名规划域不保证同一任务变体。沿用 llm-genplan 官方域文件和 split；不能直接混入 IPC 或通用 PDDL 生成器中的同名实例。是否出现有价值的失败、是否被当前模型轻易解完，要通过后续小试判定，不能根据旧论文分数预定。

### 3.2 符号发现入口

主任务池采用 **LLM-SRBench**，首个机制分析子集建议从 LSR-Synth 的物理振荡问题开始；随后扩大到其他科学子集与 LSR-Transform。物理振荡便于讨论周期、阻尼、残差与结构修改，并有同分布和分布外数值评价的依据；具体公式清单、难度分层和隔离方式仍需静态核查后冻结，不能按最终测试表现选题。

[LLM-SRBench，ICML 2025](https://proceedings.mlr.press/v267/shojaee25a.html)及其[官方实现](https://github.com/deep-symbolic-mathematics/llm-srbench)已纳入 LaSR、LLM-SR 等方法。建议以 **LLM-SR 的程序表示和数值拟合作为执行参照，LaSR 作为概念更新基线**。LaSR 已在 [NeurIPS 2024 正文 §3、Algorithm 1](https://papers.nips.cc/paper/2024/file/4ec3ddc465c6d650c9c419fb91f1c00a-Paper-Conference.pdf)明确共同演化候选公式与文本概念。固定 LLM 不禁止拟合公式常数；这些参数不属于基础模型权重。

数据边界：官方数据卡中的五个 `split` 是任务类别，每条方程还各有观测点层面的训练／测试划分，LSR-Synth 另有 OOD 观测。跨方程研究需要另外设计按结构／来源族隔离的划分，不能把这五个类别误当成已经提供的机制训练集与测试集。截至本轮核查，[Hugging Face 数据页](https://huggingface.co/datasets/nnheui/llm-srbench)要求登录并同意分享联系信息才能访问数据文件；本轮仅核查公开说明，未申请访问、未取得受限数据，具体方程族与数值文件仍待核验。

不能把“规划侧用 llm-genplan、符号侧用 LaSR”本身称为统一方法验证。它们首先是各任务的成熟参照；最终若主张共同机制有效，两边还必须接入同一策略更新规则。

### 3.3 共同机制的研究起点

建议把 **GEPA 式轨迹反馈驱动的策略提示优化**作为可拆解的共同比较入口，优化变量明确限定为 S，而不是同时搜索所有代码和所有提示。[GEPA，ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html)支持从执行轨迹提出、检验提示更新；但把它同时适配到本稿的两套执行器，是**本项目建议的适配**，不是原论文已完成的配对。

此处只确定比较逻辑，不预先锁定 GEPA 为最终方法，更不把普通适配当作新颖贡献。可先检查现有更新器在相同父产物、相同反馈下如何产生修改，再据稳定失败现象决定改反馈组织、策略修订还是候选选择。

## 4. 两条一起推进的实验顺序

两边同时做任务准备、基线复核和日志定义。机制诊断先在规划侧定位较明确的错误，在符号侧及时复核是否仍能观察到相同更新问题；不要求完成一整条研究后才开启另一条，也不从第一天同时开放大量模块。

1. **配对观察单步修改。** 保存父产物与执行经历，各组从同一起点出发，记录包括失败和弃用在内的全部修改。检验修订是否改善独立评价，而非只看最后被挑出的赢家。
2. **区分搜索与策略更新。** 保留相同长度的产物搜索：一组用固定策略，一组根据执行反馈更新策略。再用等资源独立采样选择解释额外尝试的收益。反馈数量、候选数与所有模型调用分别记录。
3. **检验策略的后续作用。** 在未参与策略选择的新父产物／搜索状态上，比较旧策略和新策略。必要时重置候选池，只带走策略，避免把最佳成品缓存当成更会改进。
4. **恢复连续更新。** 单步现象确认后，看改善能否累积、错误经验是否持续放大，再冻结共同规则扩大两边的任务覆盖。

最低对照包含：不做策略更新但保留同样搜索过程；执行反馈直接修订；共同成熟更新器；针对性改动。规划侧再以原版 llm-genplan 及适用的传统规划器校准，符号侧用 LLM-SR、LaSR、PySR 校准。传统方法回答成品质量问题；策略开关回答更新增量问题，两类比较用途不同。

## 5. 评价层次不能混淆

| 检验对象 | 规划侧 | 符号侧 |
|---|---|---|
| 产物泛化 | 同一个规划程序解决未见实例 | 同一个公式预测未见输入点 |
| 更新策略泛化 | 新父程序、新搜索状态；进一步才是未见规划域 | 新父公式、新搜索状态；进一步才是未见方程或方程族 |
| 同一机制的跨类适用 | 同一更新规则用于规划 | 同一更新规则用于符号发现，各自可学习不同策略内容 |

两边都分别隔离修改用、选择用、最终评价用信息。符号任务除观测点划分，还要按目标方程／来源族隔离跨题更新；同一公式换系数或改变量名不能自动算新独立任务。规划领域小样本多实例的结果不能冒充已验证跨域泛化。

共同过程指标可用：单步改进率、退化率、原有成功行为损失、冻结策略对新父状态的增益及完整搜索曲线。规划成功率与符号 NMSE 各自报告，不直接相加成一个总分。独立重复以完整更新运行为主，同时说明实例／方程层的相关性；样本量与检验方法在小试后据变异性决定，不在未运行时预设显著性。

## 6. 近邻边界与待落实事项

[Strategy Refinement and Reflection](https://arxiv.org/html/2508.13876)已在规划中加入伪代码策略修订与代码反思；[LaSR](https://papers.nips.cc/paper/2024/file/4ec3ddc465c6d650c9c419fb91f1c00a-Paper-Conference.pdf)已有概念提炼；[Deliberate Evolution](https://arxiv.org/html/2606.04360v1)已有算子选择、残差诊断、反思记忆，本文按作者预印本使用。已有研究使“诊断—反思—更新”不能单独成为创新点。

进一步的直接近邻：Deliberate Evolution 的附录 C.5 已将可见训练数据再分为常数拟合与内部验证部分，并将内部验证误差用于候选选择和记忆更新；[RESTART，ICLR 2026，§4.3](https://proceedings.iclr.cc/paper_files/paper/2026/file/72416ded78a439907ff72165ac9c56e0-Paper-Conference.pdf)已有改进门控、结构记忆合并及容量淘汰。因此，“加验证集”“有用经验才入库”均不能单独称为本项目的新机制。DE 的 Algorithm 1 在每个问题初始化空记忆，不能据此声称其已经证明跨方程持久策略的有效性；RESTART 使用预训练符号回归求解器处理子问题，其系统组成也需在比较时交代。

本轮只完成路线确认及共同实验结构。接下来应落实两个执行器的任务清单与版本、反馈可见范围、P/S 的具体表示和第一组基线；新方法应建立在可重复的失败现象上。跨题持久更新、跨任务直接迁移和更新器自改写均需相应实验，不能因同时选择两条路线就视为已完成。
