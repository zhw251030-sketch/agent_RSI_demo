# 基函数策略开发轮：独立结果审查

日期：2026-10-22。审查对象为冻结实现 `7eeb4c0`、准备提交 `d76a952` 下的完整 SDK 模拟 `runs/basis-trial/sdk-preflight-v01` 与真实停止轮 `runs/basis-trial/measured-v01`。本审查只读原始请求、响应、事件、预算、准备包、旧学习材料和冻结源码；没有新增模型请求、拟合、候选执行或真实 CSV 数值读取。

## 结论

完整模拟通过，但真实轮在唯一策略提案响应之后按冻结契约停止。模型返回的四条规则合法；必填的辅助解释为 **4,223 字符**，超过实际工具 schema 的 **2,000 字符**上限，因而整个提交未被接受。实际发生 1 个真实请求，0 个接受策略、0 个 SDK ActionEvent、0 个父基线、0 个 actor 请求和 0 次真实任务 fit/predict/sandbox；其余 12 个模型位置未开始。

这既不是超时，也不是费用额度耗尽，更不能解释为策略改进无效。当前没有任何 S0/S1 的真实任务对照分数；它暴露的是辅助解释限制能在科学测量开始前中止整轮的工程脆弱性。严格拒绝符合该轮事前契约，不能事后删除或截断解释以追认原提案。

## 完整 SDK 模拟的独立核对

外部[准备冻结](../experiments/basis-trial-v01-preparation/freeze.json)的 SHA-256 为 `9ce2abd33c08af00e5efd65da154cd86f3be3aed7c09a810523ef6c202482b80`。审查逐一重算 165 个运行文件与准备文件哈希，并核对模拟 readiness、invocation 和冻结文件一致。

独立读取 13 个完整请求、原始响应、预算条目与 SDK 事件，确认有 13 个实际 SDK ActionEvent，均与各自工具调用 ID 绑定。A、B 每组六个 actor 请求去除唯一的策略字段后，各只剩一个完整请求哈希，合计两组共同输入。12 个模拟 actor 中，A-r1-S0 与 B-r1-S1 分别完成 A→B、B→A 的一次换项，其余 10 个保持父集合。

14 份人工测量记录包含两父基线和十二终稿。审查没有调用模拟测量器，而是独立用固定人工目标 `[1,2,3,4]` 与保存的零预测计算 SSE、目标总体方差及 NMSE，全部得到 NMSE=6，与记录一致。这些是固定假回复和假执行回执，不能算 14 次真实拟合或 28 次真实沙箱执行。模拟账本的 usage、预留和估算费用也全部排除研究账本。完整最大请求为 88,898 字节，小于 98,304 字节上限。

预演证明这些固定路径能完成实际 SDK Conversation 的序列化、接收、Action 派发、宿主绑定和审计；它不保证真实模型一定遵守所有工具约束。开发期旧模拟的宿主大 JSON 解析错误与最终成功模拟应分别保存，不能混称同一次无错误运行。

## 真实停止的直接证据

真实原始响应 SHA-256 为 `200fe03c933537ac13207912e4bc6e912d521d31b0c0d9f64d8328f107373e92`。它只有一个 `submit_policy` 调用，参数恰好为 `rule_ids` 和 `explanation`，四条规则为：

```text
R01 → R05 → R04 → R08
```

四个 ID 都在旧八规则目录内且互不重复；独立调用冻结 `validate_policy` 校验通过。解释全部为 ASCII，长度同时是 **4,223 个字符和 4,223 个 UTF-8 字节**，比声明上限多 2,223。实际请求的工具 schema 确实规定 `minLength:1,maxLength:2000`，不是接收器私自采用了不同限制。将保存响应直接送入冻结 `parse_policy_response` 作只读回放，得到 `ValueError: Nonblank bounded policy explanation required`，与运行中的 ValueError/ConversationRunError 及停止位置吻合。

传输回执记录正常返回，耗时 8.926116 秒；已知 usage 为 25,210 输入＋944 输出＝26,154 tokens。按既有未缓存配置费率估算 0.0608706 元，保守预留 0.2727018 元，均远低于本轮 4 元上限。响应另报告 128 个缓存输入 token，但既有费用口径仍是配置费率估算，不能把它写成服务商实际账单。

预算中的 `failed_count=0`、`halted=false` 指网络请求正常结算且 usage 已知；不表示科学工作流成功。工作流汇总明确为 stopped，策略为空，SDK 会话状态为 error。独立核对真实目录 18 个文件，没有 `policy-freeze.json`、父基线目录、`fit.json` 或 `predict.json`；事件只有系统提示、用户消息和 ValueError，未出现 ActionEvent。结合冻结调度中“策略冻结后才装载任务”的顺序，记录支持本轮没有进入新 CSV 装载及任务执行路径。学习请求中的旧训练统计仍是历史输入，不能误写成从未接触任何训练信息。

## 未接受解释中的事实核对

解释未进入有效策略，也未喂给 actor。即使后继接口减少解释约束，这段文字也不能直接作为可信经验保存。将它与实际发送的[完整历史学习包](../experiments/basis-trial-v01-preparation/learning-package.json)对照，至少有下列具体问题。

| 解释中的说法 | 原始学习材料 | 判断 |
|---|---|---|
| 两个获 promote 的符号简化分别是 4 参数、5 参数变体，误差差约 7e-7、1.4e-17 | `S-x5-r1-checked` 与 `S-x5-r2-checked` 都是同一父状态的 5→4 参数；两者 NMSE 均从 0.09180398722781567 变为 0.09180470524756017 | 参数数量和两条简化的对应关系被混淆；不是两个不同参数数的正例 |
| 1.4e-17 体现另一种可接受简化的误差变化 | `S-x5` 的 `sham_delta_nmse=1.3877787807814457e-17` 来自规范化全式与原式的差，历史另有预测数值末位差 | 将数值对照/预测差移作简化收益，证据角色错误 |
| 两个删项 probe 对 1e-5 阈值的使用不一致 | `S-v3` 与 `S-x5` 的 `epsilon` 都是 1e-5；删项损失分别为 0.0015132655690959645 与 7.180197444667247e-7 | 两个损失位于同一阈值两侧，不能据不同 verdict 推断阈值应用不一致 |

此外，S-v3 与 S-x5 本来就是不同父结构：前者含 v²、v³ 等六项，后者含 v·abs(v) 等五项；“两个 probe 只区别于被删项和差值大小”省略了不同起点与表示。暂时删项并重新拟合属于干预记录，不能与边际残差关联混为一类证据。

解释也包含有依据的局部观察，例如 P-format 的输出格式修补、声明改变而源码未改的区别，以及 train 分数不能代表一般能力。但这些正确片段不能认证全文，也没有证明该四条规则排序优于 S0。旧学习包中的 promote 是研究者规则对历史终稿的事后分类，不是本次策略已被晋升。

## 最小后继修正建议

优先在独立后继版本中让策略工具只要求真正转移的 `rule_ids`，把自由解释保留为原始 assistant 响应中的归档信息，不再让它决定合法四规则策略能否进入测量。继续严格验证规则集合、一次提交、工具名、原始 JSON、已知 usage、完整响应/输出和总预算上限；不要为解决辅助文本问题放松这些实际执行边界。

这比把 2,000 临时提高到刚好容纳本次 4,223，更直接处理故障原因。仅在提示中请求“写短一点”可以降低风险，但不能保证真实回复遵守长度；它不能替代明确的辅助文本处理契约。actor 当前也有解释上限，同类风险须在后继协议中同时考虑，而不能把仅修策略工具称为整个输出路径已无此问题。

旧原始响应可以作为后继解析器的离线回归材料，但不能在新规则下追认该轮 S1，也不能补跑剩余十二个位置。需要新版本、新冻结、新完整模拟和新运行目录；新一轮仍从唯一策略提案开始，旧轮保持 `record_consistent_incomplete`。本审查只提出建议，没有实现后继修复或发出额外模型请求。
