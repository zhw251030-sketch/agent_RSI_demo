## 2. 规划 A：正确修订出现，但成功总结也需要逐句核对

证据：[候选记录](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/trajectory.json)、[诊断](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/diagnostics.json)、[公共任务契约](../../prompts/pilot/planning.md)。

- **A001 的目标是实现正确 BFS，但“正确”尚未得到执行支持。** 它的十个返回计划均为空，VAL 全部判失败。源码确实按有向边行走、删除已经使用的 `useable`；这些规则与契约一致。但其 [`carrying(state)`](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/planning-001.py) 第 94–97 行只返回遇到的第一个 carrying 事实，第 129、142 行只使用这一把扳手生成拧紧动作。严格说，A001 的状态仍可能保存多个 carrying 事实，因此把它笼统描述成“状态只允许带一把”不精确；问题在于动作生成只选取一个，且依赖集合迭代顺序。
- **A002 提出的更快哈希/BFS 没有本轮性能证据支撑，也没有解决语义错误。** [`planning-002.py`](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/planning-002.py) 第 59 行 `carried = s` 明确只保留一把，第 64 行拧紧后清空。全部结果仍为 0/10、计划长度为零。不能从这次重构推断效率改善。
- **A003 的“可以同时携带多把”得到公共契约和随后执行共同支持。** pickup 的效果增加 `carrying(m,s)`，不删除其他 carrying，也没有空手前提；tighten 删除的是 `useable`，不删除 carrying。[第三个源码](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/planning-003.py)第 54–56、73–80、86–98 行改用集合并遍历所有仍可用的随身扳手。实际为 prompt 2/2、development 8/8；两个公开实例的可信重放均合法执行 11 个动作。该结果支持“这个程序解决了本批任务”，但没有只改一处的干预对照，不能把全部变化的效果严格归于单一修复，更不能据此断言 A 优于 B。

最终响应仍有两处说明性问题：其对 A001“排他携带”的回顾过于简化；所举 problem0 路线写成拿 `spanner3` 再拿 `spanner1/spanner2` 之一，却说可拧紧三个螺母，仅描述了两把扳手，和一次性 `useable` 规则不相容。实际通过 VAL 的源码与结果不受这段不准确文字影响。来源：[request-0004.response.json](../../artifacts/diagnostic-comparison/2026-10-20/planning_A/final-response.json)。

## 3. 规划 B：局部诊断正确，修订却改写了任务规则

证据：[候选理由与分数](../../artifacts/diagnostic-comparison/2026-10-20/planning_B/trajectory.json)、[诊断](../../artifacts/diagnostic-comparison/2026-10-20/planning_B/diagnostics.json)、[公开任务契约](../../prompts/pilot/planning.md)。

### B001：把一种策略写成必要步骤

“空计划不能完成目标”“每次 tighten 消耗一把可用扳手”都有证据。“有效计划必须取一把、走到螺母处、拧紧、再取下一把”则不是任务规则，而是候选自己施加的策略限制。两个公开实例的 link 均为 `shed → location1 → … → location4 → gate`，所有目标螺母在 gate；该单把往返策略在有向图上无法继续取扳手。契约从未禁止沿途先收集多把。

B001 对公开 problem0/1 的可信重放：`executed_actions=7`、`plan_length=7`、`first_failed_action=null`，最终还缺 `tightened(nut2)`、`tightened(nut3)`。这支持“输出动作都合法，但目标未完成”，不支持“任务无解”。

### B002：诊断基本正确，提出的修订没有解除限制

其理由指出上次只执行一次拧紧、到 gate 后无法再取扳手。该判断由上述重放、公开有向图以及 B001 第 91、96–97 行的取扳手/退出代码共同支持。

但它宣称通过“reverse BFS”“不要求从螺母位置返回”修复。[实际代码](../../artifacts/diagnostic-comparison/2026-10-20/planning_B/planning-002.py)第 24–27、36–47 行仍是正向邻接/BFS；第 119 行仍从**当前位置**搜索下一把扳手，第 131–134 行仍每次只拿一把后立即走到螺母处。公开实例的执行再次停在 7 个合法动作；轨迹记录 `goal_nuts` 调用两次、`do_pickup`/`do_tighten` 各一次，第 121 行不可达分支命中四次，第 138 行无进展退出命中一次。观测支持“识别出了被困现象”，但代码并未落实能避免它的策略。

### B003：可直接反驳的规则改写

其理由先正确复述 B002 的调用计数和 gate 为汇点，随后声称唯一一致解释是行走实际可双向，并称“没有发明新位置对”。这是关键跳跃：**当前取用策略不完整，不等于公共动作定义错误。** 公共契约明确说明 `link` 有向，反向不能假定；walk 必须具备 `(link start end)`。多把携带本来就是公开契约允许的另一种策略。

[`planning-003.py`](../../artifacts/diagnostic-comparison/2026-10-20/planning_B/planning-003.py)第 27–28 行为每条边加入反向邻接，第 53 行仅沿这份对称邻接搜索，第 68–72 行直接生成 walk；没有其理由所声称的另一个有向 BFS fallback。即使无向“位置对”早已出现，新增反方向仍是在发明一个不存在的有向前提。

随后执行提供了直接反证：两个公开实例均在成功执行前 7 个动作后，于零基索引 7 尝试 `(walk gate location4 bob)`；可信重放报告缺少 `("link", "gate", "location4")`。计划长度分别变为 21、15，但 VAL 仍判失败。其他八道开发题也失败，不过未开放其精细诊断，不能据此断言八题的第一失败动作完全相同。

这里能确证的是“一个真实诊断被接到一个违反公开规则的修订上”，不是“增加诊断必然有害”。本会话之后没有最终模型响应，因此不能声称模型看见该反证后拒绝改正或已承认错误。

## 4. 符号 C：格式与引用存在，不保证结论由证据推出

证据：[候选理由与分数](../../artifacts/diagnostic-comparison/2026-10-20/symbolic_C/trajectory.json)、[残差摘要](../../artifacts/diagnostic-comparison/2026-10-20/symbolic_C/diagnostics.json)。三次理由都有 Observation / Hypothesis / Prediction / Check / Evidence / Change，且 `oscillator1:residuals` 确实存在。本文发现的问题发生在解释的内容，而非仅缺少这些字段。

### C001：值得尝试的线性形式，不是已识别出的物理定律

常数起点的 x 四分位箱均值依次为 −0.066885、−0.044304、0.022675、0.088514，单调变化的描述正确。v 箱均值为 0.007141、−0.003456、−0.014355、0.010671：相对 x 趋势较小，但“对称”只是粗略措辞。它提出线性 x/v 形式，是合理的探索假设；这些边际分箱本身不能识别恰好线性的恢复力，也不能把关联解释为已知物理原因。

实际 NMSE 从 1.0 降至 0.09694021，支持该两参数线性形式在已用训练点上解释了大量变异。没有单独去掉 x 或 v 的对照，不能将这一下降完全归给某一个项；也不能把训练拟合称为恢复了真方程。

### C002：“有偏差”正确，“偏差是主导误差”错误

提交 C002 时，C001 的整体残差均值为 0.002040886，RMSE 为 0.02056634，标准化偏差为 0.03089682。添加截距以尝试减小均值，是可检验且合理的提案。

但 x 四箱均值实际为 **0.00227079、0.00060042、0.00309748、0.00219485**，不能当成已经验证的均匀常数偏移。更明确的量化反证是：同一样本上 `MSE = 残差方差 + 残差均值²`，由现有摘要直接计算，`bias² / MSE = 0.00984744`，即均值偏移平方只占约 **0.985%** 的原 MSE。因此“主导剩余误差是常数偏移”不成立。标准化偏差用目标标准差归一化，并不是显著性检验。

C002 执行后均值降至约 1.37e−17，NMSE 从 0.09694021 降至 0.09591726，相对下降约 **1.055%**。这支持“加截距的模型减小了整体均值和少量训练误差”，不支持“真实加速度必含重力、平衡位移或驱动偏置”。模型同时重新拟合所有系数，所以实测总下降不必恰好等于旧残差的均值平方。

### C003：高 v 箱误差大，不能推出非线性 v 项为必要结构

提交 C003 时，C002 的 v 四箱 RMSE 为 **0.01242151、0.01893389、0.01190174、0.03193127**。最高 v 箱误差较大是真实观测；其相对前三箱的倍数分别为 **2.57、1.69、2.68**，不是一致的 2.6 倍。该箱对应 `v ∈ [0.09524425, 0.28213635]`，分箱按有符号 v，而非 |v|；不能不加区分地升级成“大 |v| 的一般规律”。

这些是 `E[r² | v箱]` 的边际摘要，并未区分条件均值失配、条件方差、与 x 的关联、遗漏的 x 或交互项等解释。因而“nonlinear-in-v terms are required”超出了证据；对具体幂次标 `evidence_insufficient` 并不能使更上层的“必需非线性 v”结论自动成立。仅凭四个箱均值，也不能把 x 残差称为已确认的随机噪声。

实际加入 v² 后 NMSE 从 0.09591726 降至 0.09576767，相对下降约 **0.156%**；最高 v 箱 RMSE 从 0.03193127 **略升**至 0.03195450。结果支持“这一具体项只带来很小的总体训练改善，未缩小目标箱的 RMSE”，没有证实其提出的缺失机制。

### 最终响应：能承认预测未获支持，但又把失败升级为噪声判定

[request-0008.response.json](../../artifacts/diagnostic-comparison/2026-10-20/symbolic_C/final-response.json) 正确注意到高 v 箱 RMSE 基本未变，并说明相应预测没有得到支持；这是本轨迹中可观察到的解释修正。

但响应正文随即断言这部分方差是模型无法拟合的噪声，finish 文本也倾向将其写为噪声而非遗漏的确定性项。一次 v² 扩展效果小，只能限制这个具体尝试，不能排除其他确定性结构或证明不可约噪声。finish 的“剩余不确定性”又列出 `v|v|`、`x*v` 等可能性，说明同一响应内仍混用了确定断言和保留可能性。其训练分数、无泛化结论的限定可以保留；噪声归因不能照抄成研究结论。

## 5. 本轮可支持的机制问题与后续界限

1. **观测真伪与解释成立是两道不同检查。** B003 的计数和汇点描述大体正确，但“唯一解释”违反公共契约；C 的证据 ID 真实存在，却未支持其“主导”“必要”“噪声”等强结论。后续可把规则矛盾、量级不符和证据不足作为分开的诊断类别，不能把存在引用视为解释通过。
2. **有预测字段还需要定义预测对象和核对时点。** C002 的“均值下降”得到了支持，“主导误差”被数值反驳；C003 的总 NMSE 略降与目标箱误差没有下降可以同时成立。后续机制应明确究竟检验整体误差、分箱均值、分箱 RMSE，还是特定程序分支。
3. **正确的行动不需要附带已确认的因果解释。** 加截距、尝试 v² 可以作为受预算约束的探索；应保留结构原因尚不确定，而不是为了执行一个尝试先把结构说成必要。规划侧则可在生成动作前检查它与公开前提是否矛盾。
4. **当前材料不能回答 C−B，也不能把 A/B 的一次差异归因于诊断。** planning_C、symbolic_A/B 没有启动；已完成部分没有随机重复，执行顺序固定，规划 B 又受到会话停止影响。开发起点和数据参与过规则设计，十题是同一程序的批量评价，不是十次独立机制重复。

后续若设计新对照，应先另行冻结新搜索状态、独立的策略选择/评价划分、观测解释审查口径及预算；本轮不追加候选、不恢复会话、不改写成绩。本文提出的是从这次开发轨迹得到的待检验问题，不是新机制已有效的证据。
