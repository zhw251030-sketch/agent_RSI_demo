# 三条件编辑门

日期：2026-10-24。状态：离线接口完成，尚未进行新的模型调用。

## 目的

旧 v02 已经显示，同一个较好父结构会被多次改坏，但它不能区分“模型生成了有害候选”和“宿主允许有害候选执行”。因此下一轮把候选生成和候选接受拆开：同一个已生成候选分别经过三种条件，避免把模型随机输出差异误认为检查机制效果。

## 三种条件

| 条件 | 是否读取编辑证据 | 编辑级状态 | 作用 |
|---|---|---|---|
| `no_check` | 否 | 固定 `supported` | 基线，所有合法候选进入执行 |
| `sham_check` | 否 | 固定 `supported` | 控制记录和额外流程，但不含有效信息 |
| `real_check` | 是 | typed check 的真实结果 | 只有 `supported` 才执行 |

三组使用同一最终接受门：`execute_only_when_supported`。因此无检查和 sham 的区别只体现在记录原因，真实检查可能因为 `contradicted` 或 `unknown` 保留父结构。检查失败不会默认为放行。

保持原结构的 `keep` 候选不需要结构检查，单独记录为 `check_applicability=not_applicable`，直接保留父结构；它不计入检查状态校准的分母，但仍计入候选生成和父结构保留统计。

## 当前实现

`rsi_eval/edit_condition_gate.py` 只产生审计记录和 `execute_candidate` / `retain_parent` 决策，绝不执行候选。它接收已经由 `edit_evidence` 验证的具体编辑。旧 v02 运行器保持冻结；下一步的新运行器在候选接受后、拟合执行前调用该门。

`analysis/basis_edit_comparison/shadow_outcome.py` 会先冻结每个候选的三条件门结果，再接收统一的候选/父结构分数。它检查冻结哈希，禁止缺失条件或篡改后验记录；`prevented_harm` 只在真实检查保留父结构且 shadow outcome 显示候选退化时计数。后验结果不能改变已冻结的 `final_action`。

## 实验边界

这一接口还不是机制效果结果。正式小试前仍需固定：父结构来源、候选生成位置、三条件的同候选绑定、typed check 的阈值或规则、失败处理、训练/验证分数和预算。封存数据不能进入编辑前检查。报告至少包括有害编辑率、父结构保留率、候选执行率、检查状态覆盖率以及训练和验证指标变化。
