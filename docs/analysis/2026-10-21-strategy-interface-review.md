# 策略接口交叉审查

范围：新角色执行器、历史学习包、任务与actor输入构建、原始记录绑定、两个策略选择结果的评价权限、准备脚本与合成校准。审查没有运行八份新起点或读取选择/评价数值数据。

## 发现及处理

1. 合成公式原稿使用 `equation(X, params)`，与真实worker的逐列调用不兼容。已改为 `equation(t, x, v, params)`；最终是否通过以服务器真实校准记录为准，不能拿本机跳过当通过。
2. 文件引用原可接受双斜线或内部绝对路径，同一文件可能形成两个不同路径标识。现强制规范相对POSIX路径，拒绝通过别名绕过测量复用检查。
3. 仅核对外层success对应VAL valid还不够；外层candidate_error携带内层valid也可能使固定组被错误降分。现同时检查反向一致性及sandbox阶段状态，回归负例覆盖此错误晋级途径。
4. 共同上下文不能只验证哈希。task_text、例题和目标现由固定契约构造；基线反馈逐项绑定原始角色执行收据，不允许把后置静态诊断写入上下文再重算哈希。
5. 生成阶段的冷启动指令不适合原样加入修订提示。新任务契约只提取公开规划接口/域规则及符号数组/参数约定，不继续告诉actor“没有起点或反馈”。

## 确认的边界

- 学习包完整覆盖预先指定两个历史批次的24份终稿，不代表项目全部历史。来源校验包含520份旧原始文件；相同状态上的重复与不同task instance不能被解释成独立策略学习重复。
- 两个提案分别调用选择器，必须使用同一共同上下文和分配；请求和最终测量不得跨重复复用。synthetic记录不能打开真实评价权限。
- 权限对象在每次评价任务读取前重新回放。评价源码在学习题上运行仍需由未来调度器先检查起点阶段；底层task-role执行器无法自行知道任意源码的研究角色。
- evaluator_sha256认证明确列出的源码文件指纹；它不认证Python、NumPy、SciPy二进制或机器环境。版本、依赖与沙箱须结合既有环境记录及本轮服务器校准解释。
- 绑定器核验可信客户端记录之间的一致性，没有供应商签名或独立写入时间证明。未来SDK控制器仍须保存真实dispatch、response、工具接受及首请求前冻结证据。

截至此审查，没有剩余已发现的阻断性接口问题；实际测试和校准结果另见本轮验收文件。未据模拟选择或工具测试声称任何新S收益。
