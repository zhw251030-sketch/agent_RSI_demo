# 基函数策略 v0.2：完整真实对照与退化行为

日期：2026-10-22（Asia/Shanghai）。实现 `ed96ac9a`，执行冻结 `6eba8793`。**本轮完整执行了 1 次策略提案和 12 次公式修订，13 次真实请求全部接受。新策略在本次均值上较低，但仍会破坏较好的起点，尚不能证明稳定机制优势。**

## 本轮解决了什么

上一轮 v0.1 首次策略响应中的规则合法，但必填解释 4,223 字符超过 2,000 上限，整个提案被拒绝；没有任何公式对照。本轮没有续跑或追认旧响应，而是另建 v0.2 和新目录，重新生成提案。

[SDK控制器](../../extensions/basis_trial_v02/sdk_controller.py)将工具收紧为两个真正参与决策的对象：`submit_policy({rule_ids})` 和 `submit_basis({feature_ids})`。可选 assistant 文本原样归档，允许空缺，不进入接受条件或后续策略输入；完整响应仍有 64 KiB 上限、输出仍限 8,192 tokens。工具参数中多余的 `explanation` 仍拒绝，因此新契约不追认旧违规参数。

旧基函数编译器要求说明字段。新版通过显式宿主转换附上固定标记 `Host-generated execution payload; no model explanation is used.`，同时保存业务对象、执行对象和 `host-conversion.json`。该文字不是模型生成或科学解释。[审计器](../../extensions/basis_trial_v02/verify.py)重新计算转换，逐一核对原始响应、SDK Action、接受回执、执行公式与实际测量，避免接口解耦变成无记录的参数改写。

本轮13个真实响应的 assistant content 全部为空或 null。它们正常提交了 ID，但没有自由文字可用于推断模型为何选某个结构；本报告只根据可观察输入、选择与结果讨论。

## 对照究竟在做什么

[调度器](../../extensions/basis_trial_v02/run.py)让固定 MiniMax-M3 从完整旧学习包提出一份新外部策略 S1。包内是原两个历史批次的24条相关转移、4个已见状态及原源码，没有加入旧失败提案或本轮父结构评分。S1 冻结之后才读取 oscillator1/train、计算父基线并开始12次修订。

- S0：R03/R04/R06/R08，强调任务约束、准确理解指标、关联不等于必要性、保留正确行为。
- 本轮 S1：R01/R02/R05/R08，强调接口类型与顺序、最早实测失败、诊断到实际编辑的对应、保留正确行为。

两者是同一个八规则目录中四项的选择与排序，模型权重没有更新。S1 是本轮待比较提案，未经过新选择集验证，也没有被晋升为正式策略。完整规则见 [revision_policy.py](../../rsi_eval/revision_policy.py)。

任务来自已下载的公开原始 LLM-SR：给定 oscillator1 训练数据中的位置 x、速度 v，构造预测加速度 a 的公式。使用10个三阶以内单项式组成的完整字典，每个结构固定4项、必须含常数；允许保持或只替换一个非常数项。宿主统一拟合系数，模型只选结构。

两个研究者指定的起点是 A={1,v,x,xv} 和 B={1,v,x,x²}。每个起点分别用 S0/S1 各生成三次，固定交错顺序，所有终稿都评分；模型看不到其他终稿或其得分。每父六份实际SDK完整请求除 `repair_policy` 外逐字节对应一致，两个起点之间当然不同。共同反馈包含父误差、系数和有界残差摘要，不包含原始CSV或逐行预测。

这样安排是在控制参数个数、数据、反馈、执行器和请求数量后，观察规则改变是否影响结构选择。固定4项避免单纯增参数造成的混淆，但不保证函数族复杂度、条件数或数值计算量相同。设计和冻结原件见[协议](../experiments/2026-10-22-basis-trial-v02-design.md)与[准备包](../experiments/basis-trial-v02-preparation/design.json)。

## 全部真实结果

NMSE 越小越好。父 A=0.004529830112440761，父 B=0.0958837205768955；预先固定的改善/退化阈值为绝对差 1e-5。下表所有终稿都保留 {1,v,x}，因此用第四项简写完整结构，未省略任何请求。

| 起点 | 策略 | 重复1：第四项 / NMSE | 重复2：第四项 / NMSE | 重复3：第四项 / NMSE | 相对父起点 |
|---|---|---|---|---|---|
| A（原 xv） | S0 | x² / 0.09588372 | x² / 0.09588372 | xv² / 0.07155303 | 三次退化 |
| A（原 xv） | S1 | xv / 0.00452983 | x² / 0.09588372 | x² / 0.09588372 | 一次保持、两次退化 |
| B（原 x²） | S0 | v² / 0.09576767 | x²v / 0.08825805 | xv / 0.00452983 | 三次改善 |
| B（原 x²） | S1 | x²v / 0.08825805 | x²v / 0.08825805 | xv / 0.00452983 | 三次改善 |

共12次合法终稿：11次单换项、1次保持；共5种不同结构，不能称12种独立公式。四组各有2、2、3、2种不同结构。保持原结构的终稿也重新拟合一次，未复制父成绩；同结构在固定数据、初值和拟合器下得到相同结果。

描述性均值：A 下 S0=0.08777349、S1=0.06543242；B 下 S0=0.06285185、S1=0.06034864。两起点的组内中位数分别相同（A均0.09588372、B均0.08825805）。按预设重复编号逐对看，A 是 S1 胜/同/负，B 是胜/同/同；这六对不是六个独立任务，也未配同一随机种子，不能据此作显著或稳定优势结论。

最值得研究的现象是 **A 的五次结构修改全部退化**：原来较好的 xv 被替换掉，其中四次变成较差的 x²。S1 的“保留正确行为”规则在两次重复中也未阻止它。B 的两臂都能找到 xv，最佳结果完全相同；不能只报 B 的约95%误差下降并把它归因于新策略，因为旧策略也得到同样结果。

这提供了一个可执行的机制问题：反馈如何帮助 Agent 判断“该改哪里”和“何时不改”？当前结果显示，规则提示不构成实际的改进保证；结果本身并不解释误改原因。输入虽有残差和系数摘要，不能将边际残差直接当作某个基函数必要性或替代收益的证据。

这是一个已见 oscillator1/train 上的开发对照，只有两个相关人工起点、一次策略学习及每臂三次生成。没有测试集预测、跨任务复现、策略晋升或权重更新；公开标准数据的来源不能自动赋予这个小子集独立泛化结论。机制上仍是有限规则选择，不是更新器递归自改写。

## 下一步应解决什么

先围绕五次 A 退化做离线机制诊断：用已保存父/子成绩区分“提案质量”和“是否部署退化提案”，并审计模型可见摘要能否区分这些编辑。可离线回放统一的父子收益接受规则，明确它防止已测训练退化是规则定义的结果，不能称为学到的新能力。

随后在同一开发边界内准备少量可执行、与具体编辑绑定的检查，比较真实检查、等预算无信息检查与不检查条件；先明确检查如何改变提案/选择，且两策略臂采用同一部署规则，再另行冻结实验。要推广到规划，应复用“提出编辑—获得针对性证据—选择保留或部署”的抽象，而不是照搬多项式规则。当前不追加本轮样本、不重跑、不启动168请求草案或封存评价。
