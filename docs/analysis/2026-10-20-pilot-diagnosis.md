# 首轮小试的失败诊断与下一步假设

日期：2026-10-20。依据是原样保存的候选源码、模型提交理由、公开任务接口和真实执行记录。下述控制流分析为运行结束后的只读审查，没有手动修补候选或追加模型请求；没有另做诊断修复实验。

## 规划：一次正确修错，随后引入接口错误并误判原因

[公开任务说明](../../prompts/pilot/planning.md) 明确给出 `("at", "bob", "shed")`，域定义是 `at(locatable, location)` 和 `carrying(man, spanner)`；两道公开示例也有这个初始事实。

1. [planning-001.py](../../artifacts/pilot/2026-10-20/planning-001.py) 将整个状态中的事实直接拆成三个元素，但 `("loose", nut)` 和 `("useable", spanner)` 只有两个元素。十题均得到 Python 异常反馈。模型第二次修改关于混合元组长度的诊断与源码相符。
2. [planning-002.py](../../artifacts/pilot/2026-10-20/planning-002.py) 加入长度检查，却在 `_man_location` 中检查 `f[2] == man`、返回 `f[1]`，把对象和位置顺序反了。合法初态中找不到人的位置，于是 successor 生成跳过该人，队列处理初始节点后就为空，最后返回空计划。
3. [planning-003.py](../../artifacts/pilot/2026-10-20/planning-003.py) 的提交理由声称上一版空计划“证明 BFS 达到了 300k 节点上限”，因而大幅改成构造法。但 `_man_at` 保留相同反序错误，得到 `cur=None`，找不到从 None 到螺母位置的路径，最终仍返回空计划。

`plan_length=0` 本身无法区分搜索耗尽、上限中断和接口误读；没有节点计数或超时证据支持“状态爆炸”的结论。相反，公开输入与源码给出“没有任何合法后继”的充分失败路径。这里只读分析控制流，未把它夸写成额外运行仪器测得的事实。

002/003 的 carrying helper 也把人和扳手顺序反了，这是被位置错误先遮蔽的缺陷。003 文档字符串还声称有 BFS fallback，但入口只有 `_construct`，失败后直接 `return []`；其 `_bfs_route` 只是道路寻路，并非完整规划后备搜索。即使修正 helper，“先到螺母处再找扳手”的策略也与公开题目的单向道路冲突：螺母位于没有出边的终点 gate，扳手在上游。后两点是额外静态缺陷，不能冒充已经做过逐个修复消融。

全部规划候选都为 0/10，因此按平分保留更早候选的规则，incumbent 一直是空计划起点。后续候选的 parent_id 由此都指向 planning-000；模型仍能看到此前失败历史，也明显复用了自己的代码。**记录的选定父候选不保证模型实际遵守从该源码开始修改的意图**；这也是后续设计应区分的控制器行为与模型行为。

## 符号：函数族训练拟合改善，不等于发现真实规律

三个模型产物依次为：

- `a = -k*x - c*v`，train NMSE 0.0969402。
- `a = -k*x - c*v - d*x**3`，train NMSE 0.0950557。
- `a = -k*x - c*v - d*x**3 - c2*v*abs(v)`，train NMSE 0.0918047。

系数由评价流程在 train 上拟合，外层校验参数并在独立预测进程后重新评分；这里表达的是模型提交的函数结构。源码见 [全部快照](../../artifacts/pilot/2026-10-20/README.md)。观测支持“这些更丰富的函数族在当前训练集得到更低误差”。

模型在第三次提交理由中说，小幅度加入位置三次项的收益意味着残差“主要由速度通道主导”。但它只获得聚合 MSE/NMSE，没有残差与速度／位置的关联统计，也没有控制变量的比较，因而该原因解释仍是假设。增加参数和函数项本身会扩大拟合能力；训练误差降低不能证明这些项是真实物理机制。

## 对后续研究的作用

本轮暴露了一个两侧共同可研究的现象：Agent 把低信息量反馈上升成具体原因解释，再据此选择修订；解释可能与已有公开事实矛盾，也可能超出反馈所能支持的范围。它为机制设计提供实例，尚未证明该现象普遍、某种修复有效或该想法具有新颖性。

下一轮可检验的候选规则是：每个诊断先写出可被验证或反驳的预测，优先检查已公开的接口事实；在诊断尚未支持时限制大幅结构改写。规划可区分“没有找到人的位置”“没有后继”“达到搜索上限”；符号可区分“加入项降低训练误差”与“残差主要依赖某变量”。具体允许哪些诊断反馈，需在下一轮协议中预先固定。

实验需要同一起点、同一基础模型、相同请求与评价预算的普通修订对照；若增加反馈信息，还需把“更丰富反馈的作用”和“验证诊断这一规则的作用”拆开比较。机制选择使用的状态与后续评价状态必须分开，不能只在这条已看过的轨迹上修到成功。成熟基线、近邻方法和独立实验单位仍须核查；当前未实现或运行该新规则。
