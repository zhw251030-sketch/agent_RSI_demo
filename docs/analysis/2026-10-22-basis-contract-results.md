# 符号结构提交接口：实现、人工校准与研究意义

日期：2026-10-22。实现 `a19ac1cf`，执行前冻结及人工校准运行版本 `cd91f239`。本轮完成可检查的基函数提交接口、统一系数拟合、OpenHands 工具层适配和服务器人工数据校准。没有读取真实任务 CSV、产生新模型请求、学习/选择策略或评分封存集。

## 为什么做这一步

上一轮八条件真实数据诊断表明，stress 的 7→4 同族参数化几乎不改变误差却减少求解调用；bact 的相同 14 项公式也会因特征集合不同而产生明显误差差异。因此，后续如果继续允许模型任意书写 Python 和声明参数数，策略效果仍会与重复参数、特征数量、隐含执行变化混杂。

新接口把模型的可变部分限定为“选择哪些基函数”。系数、输入处理、求解器和执行环境由宿主固定。结构修订仍有实质选择空间，但其变化可以直接核验，而不依靠模型说“我删了一项/保持不变”。这是一项实验控制，不是已经证明的新 RSI 方法。

## 现在模型提交什么

```json
{
  "feature_ids": ["m_0_0", "m_0_1", "m_2_0"],
  "explanation": "保留常数和第二变量一次项，将第一变量一次项替换为平方项。"
}
```

在宿主事先指定两个输入、K=3 时，这表示 `β0 + β1*x1 + β2*x0²`。模型不填写 β，也不能修改任务、K、数据角色、源代码、迭代上限或求解器。宿主按 `(总次数, 指数向量)` 排序，确定每个参数索引。同一特征集合换顺序、换文字解释，生成源码与结构哈希相同。

[contract.py](../../extensions/symbolic_basis_v01/contract.py)与[catalog.json](../../extensions/symbolic_basis_v01/catalog.json)共同实现这一规则。完整字典包含 1/2/3/4 输入、总次数≤3 的全部单项式，分别有 4/10/20/35 项，含常数。不是只挑上一轮有效的平方项。每次 K 必须是 1 至 min(16, 字典大小) 的整数，并包含常数；布尔值、重复项、未知项、注入文本、额外字段和空解释均拒绝。解释不进入可执行源码。

这同时明确了范围：现在是有限多项式字典内的结构选择，不支持任意除法、指数或三角函数；不能把这一受限接口称为完整无约束符号发现。各真实任务 K 和起点尚未冻结，本轮没有据人工结果为真实任务选择特征。

## 如何确保“换项”和“加项”分开

[executor.py](../../extensions/symbolic_basis_v01/executor.py)在运行前重建父子特征集合，给出实际差分，并执行宿主指定的操作限制：

| 模式 | 允许的变化 | 目的 |
|---|---|---|
| initial | 无父结构的首次提交 | 与修订动作区分 |
| swap_one | K 相同，保持原结构或恰好一删一加 | 单独观察等项数结构选择 |
| add_one | 保留全部父项，恰好新增一项 | 单独记录扩大函数族的条件 |

模型文字说“替换”但实际保持时，会记为 keep；文字不能改变集合差分。两项同时替换、以增项混入固定 K 对照、增项时偷偷删父项等情况均在装载数据或调用 sandbox 前拒绝。固定 K 仅控制名义项数，不保证设计矩阵秩、表达能力、条件数或真实计算量相同。

系数仍从 ones 开始，输入仍是 identity，保留原 `nan_to_num(nan=0, posinf=1e6, neginf=-1e6)`；沿用 NumPy 1.26.4、SciPy 1.13.1、`least_squares(..., max_nfev=100)`及原默认设置。拟合与预测使用两个独立 Bubblewrap/seccomp 沙箱；预测没有 y，宿主从预测计算 NMSE。正式数据入口保留旧 RoleExecutor 的角色、文件哈希和 EvaluationGate 检查，本轮只实际使用人工数组入口。

## OpenHands 接到了哪一层

[sdk_adapter.py](../../extensions/symbolic_basis_v01/sdk_adapter.py)提供真实 SDK 的 `submit_basis` ToolDefinition、Action 和 Executor。先验证原始响应，再允许 SDK Action 进入一次性宿主回调。原始 JSON 重复键、非有限值、多 choice、多工具调用、错误结束标记、额外参数和类型强制转换都会被拒绝。宿主 spec 深复制冻结，成功或失败回调均不可重复执行。

服务器用实际 SDK 1.55.1 完成 schema→Action→Executor→人工回调验证。该测试没有 provider 请求、Conversation 调度或真实候选拟合。因此当前结论是**提交工具层已通过验证**，尚未完成新接口与真实策略学习调度器的全流程集成；不把它称为模型端到端验收。

## 服务器真实执行的人工校准

[calibrate.py](../../extensions/symbolic_basis_v01/calibrate.py)使用预先固定的闭式函数生成人工标签。源码、输入、目标、阈值和依赖在执行前冻结；[冻结文件](../experiments/2026-10-22-basis-contract-freeze.json) SHA 为 `3877514a9b1cb620e7836c901a44a0396287caac080d049092d407cbf92a61d6`。

| 人工条件 | 结果 | 检查内容 |
|---|---|---|
| 1 输入仿射 | NMSE 4.93e-32 | 系数与常数映射 |
| 2 输入平方/交互混合 | NMSE 1.45e-34 | 列序、指数与参数顺序 |
| 3 输入三次交互 | NMSE 0 | 三变量乘积执行 |
| 4 输入混合 | NMSE 2.60e-33 | 四列接口 |
| 缺少平方项，K=3 | NMSE 0.3835616438 | 表达不充分时保留真实误差 |
| 同 K 换回平方项 | NMSE 0 | 等项数换项路径 |
| 单独增添平方项，K=4 | NMSE 0 | 增项路径与标签 |
| 常数目标 | fit 成功，NMSE 不可用 | 不将零方差误报为 0 分 |
| 两列严格共线 | NMSE 0 | 可拟合不代表系数可辨识 |
| 4 输入、16 系数 | NMSE 5.20e-32 | 上限处完整二次项＋x0³ 路径 |
| 极大有限输入溢出 | 输出 ±1e6/0，符合冻结预期 | 保留旧 Inf 保护语义 |
| 零系数乘溢出项 | 输出 0，符合冻结预期 | 保留旧 NaN→0 语义 |

缺项、换项、增项三例使用同一组人工输入和目标 `1+2*x0²-3*x1`。修改由研究者预先指定，因此它们验证操作与评分链，不能计作 Agent 自主改进。共线例取 x1=2*x0，目标 1+3*x0；初始 ones 已能精确拟合，而满足 β1+2β2=3 的系数组合不唯一。这是已知退化边界，不是从一次优化输出证明了唯一公式。

共 **10 次人工 fit + 12 次人工 predict = 22 次 sandbox**，10 次拟合全部收敛；9 例有合法 NMSE，1 例按预期不可用。拟合过程公式调用 194 次（优化器内部 184，末尾确认 10），独立预测再调用 12 次。每次 sandbox 的旧人工 warmup 另计，共 22 次；单元测试的人工数组执行不混入这些计数。所有预期在本轮一次性通过，无补抽或重跑。

这些人工多项式经过专门构造，精确拟合主要检查接口实现，不能作为真实任务精度、泛化、数值稳定性范围或 RSI 优势成绩。

## 接下来进入什么工作

下一工作单元应把此接口接入已有策略 actor，而不是继续扩大通用框架：冻结最小的父结构、K与操作模式，为固定策略和候选策略提供完全相同的结构/反馈输入；实现真实提交的原始请求与结构/测量绑定，先做完整 SDK 假 provider 小规模流程验收。

按独立结果审查，建议把下一单元缩为最多 **13 请求**的真实开发对照：1 个新策略提案；2 个预先冻结起点，每个 S0/S1 两臂各 3 次修订，共 12 个 actor 请求。假 provider 预演是该轮启动前检查；通过并冻结后，在同一工作单元执行真实对照。全部保留同策略重复与原起点评分，先检验新策略是否产生超过本次生成波动的可观察改进，不直接铺开旧 168 请求方案。三次重复仍不能建立稳定性或独立泛化结论，起点来源、两类任务适配和真实费用上限须在执行前具体固定。

方法对照需选定一个具体问题。若比较不同接受规则，两者应读取相同的重复证据；旧“一次证据对三次证据”同时改信息量和规则的设计不能隔离规则效果。下一版必须同时保留同策略重复和原起点评分，避免将生成波动或避免另一臂错误误归为 S 学习。现有 168 请求规模仍是未冻结草案，本轮没有启动新的付费实验。
