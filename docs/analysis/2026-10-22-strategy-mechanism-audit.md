# v03 后续机制审查：生成波动、编辑声明与符号表示

日期：2026-10-22。基于已完成的 measured-v03 冻结轨迹，覆盖全部32份终稿、16个配对和20份符号拟合回执。本次只分析既有记录，新增模型请求、候选执行、拟合、封存读取、S更新和权重更新均为0；716条测量是旧实验数据，不重新计为成果。

## 这一步解决什么

上一轮在一个晋升策略的四个后续状态中看到两项正向结果，但同策略也出现大幅差异。本轮把“输入相同吗、实际改了什么、函数族是否改变”分别核查，再确定下一项可检验问题。当前更值得研究的是：**怎样避免把单次偶然生成或表示变化，当成可持久采用的策略收益？** 这是由项目证据提出的开发问题，不是新颖性或有效性结论。

独立分析工具位于 [audit.py](../../analysis/strategy-v03/audit.py)，只用标准库读取固定归档与解析AST，不导入或执行候选。它逐条核对请求、实际派发和传输设置、父子源码、测量身份，并保留全部失败。手工语义判断与机械核验分开保存。

## 1. 同一输入的重复比原先两臂表显示的更多

36份请求形成21个完整字节组，其中32份actor请求形成20组。四个选择状态各有2次相同S0请求；四个后续状态各有3次相同S0请求，来自r1/fixed、r1/updated、r2/fixed。每个后续新策略只有1次生成。

下表按完整请求、实际派发与传输设置分组；同组任务ID、数据及评价器身份也一致。规划数值是一份程序在63题上的结果，不是63次策略学习。

| 后续起点 | 相同S0输入的三次生成 | 不同S*的一次生成 |
|---|---|---|
| P-eval-1 | 0/63、0/63、0/63 | 63/63 |
| P-eval-2 | 0/63、63/63、0/63 | 0/63 |
| bactgrow | NMSE 0.859961、0.804323、0.844801 | 0.728058 |
| stressstrain | NMSE 0.214373、拟合失败、0.343617 | 0.343617 |

S*的bactgrow数值比三份S0都低，但仍只有一次生成、且表示和参数数不同。stressstrain的“持平”是与原配对S0比较；另外一次相同S0已经更低。这不改写旧配对判定，却说明配对中的单次抽样不能代表策略总体表现。

全部32份终稿的字节互不相同，但其中1份与自己的父源码字节相同、4份仅文档字符串导致AST不同。其余27份AST有改变，不能由此推定27份都改变了函数行为。四次更新请求也完全相同，只产生三种策略内容；shadow仍不能追认为额外有效学习重复。

这里不估计可靠胜率、不报告p值：同一学习包、少量生成、供应商seed=null，并不支持充分的独立重复或精确总体方差。详情见[分组结果](../../analysis/strategy-v03/results.json)和[统计单位审查](../../analysis/strategy-v03/variation-design.md)。

## 2. 编辑说明有时没有落实到源码

按同一明确口径，每份终稿从解释中选择第一个具体的现时/完成式编辑或保留声明；跳过父程序诊断、因果猜测、未来意图，保留所选句内的限制词与数量。32项得到25支持、4矛盾、3未知。

| 直接矛盾 | 原说明与源码 |
|---|---|
| r1/P-select-1 updated | 声称支持逆序的字符串对象对，分支仍把第一项固定当名称、第二项当类型 |
| r1/S-select-1 fixed | 声称增加高阶多项式，实际只改docstring |
| r2/S-select-2 updated | 声称替换公式结构，实际只改docstring |
| r1/stressstrain updated | 声称原样保留7参数，实际提交6参数并改变曲率表示 |

三个未知涉及“严格线性”的条件范围、“确定性”和“完整检查”等限定，不能仅凭局部代码存在判为全面支持。

这是研究者看过结果后的人工窄谓词标注，不是盲评、全文准确率或规则遵守率。支持某个编辑存在，不代表故障归因正确，也不代表程序有效。每条都有原始引文、字符区间、父子源码SHA及行片段；[完整标注](../../analysis/strategy-v03/edit-claims.md)与[JSON](../../analysis/strategy-v03/edit-claims.json)保存全部32项。验证程序检查文字和来源对应关系，不自动证明人工语义标签。

## 3. 符号收益混合了表示、参数化和拟合因素

16份符号终稿中，7份在所说明的代数/宿主参数条件下保持起点公式，9份改变表示。相对各自起点，6份训练NMSE更低、1份更高、7份相同、2份拟合失败。8个fixed/updated配对有4个数值正向差异，全部伴随声明参数增加；另2个持平、2个不可数值比较。其中r1后续仍是同策略对照，不能算策略更新收益。

更关键的是，**声明参数个数不等于有效表达能力**。stressstrain起点形式为

`g[c01(l0*u0)(l1*u1) + q0(l0*u0)^2 + q1(l1*u1)^2] + b`。

它虽有7个参数，却可写成4个直接系数：

`β0 + β1*u0*u1 + β2*u0^2 + β3*u1^2`，

其中 `β=(b, g*c01*l0*l1, g*q0*l0², g*q1*l1²)`。反过来取 `g=l0=l1=1`，即可表示任意四个实系数。因此在无限制实系数下二者函数族相同；减少到4个直接系数并非必然损失表达能力。浮点舍入、非有限值保护及拟合路径仍可能不同，尚未作数值执行验证。

r1另一份8参数stressstrain公式只有6个多项式系数，其中一个交叉项重复。r2的bactgrow两份程序则共享11项，但分别再使用3个三变量项和4个平方项；14→15不仅是多一个参数，还换了特征。r2选择阶段的15→16也同时将可学习tanh斜率改为固定基函数线性系数。

实际拟合代码只指定 `max_nfev=100`，没有传入系数bounds；“有界”应指计算资源或评估次数。失败回执没有拟合内部详情，不能断言两次失败就是耗尽100次评估。全部源码、拟合回执与代数分析见[符号结构审查](../../analysis/strategy-v03/symbolic-structure.md)。

## 4. 从这些证据得到的具体后续顺序

先做**8次不调用LLM的研究者数值诊断**：stressstrain旧7参数与同函数族直接4系数各拟合一次；bactgrow比较原14项、全部四种等14项平方子集及完整15项，共六次。这样先分开参数冗余、特征替换和特征数量的作用，全部条件事先登记，不看结果挑删项。

这些诊断仍只用已见train，不改旧分数，不算Agent自我改进。当前仅有设计，尚未执行；具体固定项与判读规则见[下一步设计](../experiments/2026-10-22-mechanism-next-design.md)。

随后再考虑“单次证据选择”与“三次重复证据选择”的开发比较。两选择器共用一个收集结果池，但使用的信息量不同，不能称等评价信息/成本对照或新方法优势。168请求/50元是候选规模，不是本轮已冻结的可运行清单；应先由上述数值诊断确定符号表示协议。

## 5. 验证与边界

15项离线检查覆盖语法视图、同请求分组、传输差异、重复槽位、任务/评价器不一致和缺失NMSE；增加的传输与重复槽位负例在修正前失败、修正后通过。完整归档集成分析另外核对32个预期槽、16配对、每槽测量数量及所有测量的源码/策略/参数/任务绑定。

[verify.py](../../analysis/strategy-v03/verify.py)还核验235个不同引用文件、全部32条引文与行片段、16份符号记录对应关系和旧258运行文件。新分析文件不进入旧运行清单，不改变历史原档或评价程序。两端实际通过情况与哈希另存[核验记录](../environment/2026-10-22-strategy-mechanism-verification.json)。

本轮研究累计保持170请求、已知1,364,169 tokens、已知估算4.2168546元、保守预留19.5491730元；两笔旧usage未知保留。新增费用为0。本轮完成的是全量机制诊断与后继设计，没有新增任务成绩、学习策略、稳定优势或泛化结论。
