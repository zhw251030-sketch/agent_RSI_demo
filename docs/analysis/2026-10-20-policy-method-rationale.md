# 为什么先做一次经验驱动的修订规则选择

日期：2026-10-20。本文解释预先固定的设计及其研究边界；实际执行状态、策略输出与成绩另以运行归档为准。具体预算、顺序与停止条件以[开发协议](../protocols/2026-10-20-policy-transfer-v0.1.md)和[运行配置](../../configs/pilots/policy-transfer-v0.1.json)为准。

这轮要回答一个较窄的问题：**从已有失败经验中选择并排序修订规则，得到的持久策略，能否帮助同一固定模型修改另一份程序或公式？直接给它这些经验，又会有什么不同？** 这是把项目从“在固定提示下不断改答案”推进到“外部策略确实发生更新”的第一步。有限规则选择是本项目的受控实现，并非已经证明的新方法。

## 1. 改变什么，怎样区分策略和答案

沿用[联合研究设计](../research/planning-symbolic-design-2026-10-17/形式规划与符号发现_联合研究设计_v0.1.md)中的区分：产物 `P` 是规划程序或公式，策略 `S` 是指导后续修订的规则。本轮保持基础模型权重、任务定义和执行器固定；更新模型只选择 `S`，评价模型随后依据冻结的 `S` 修订 `P`。

`S` 的表示刻意收窄为八条人工规则中四条不重复规则的有序 ID。例如初始策略 `S0 = [R03, R04, R06, R08]`，依次强调保持环境语义、准确使用证据、考虑其他解释和避免无关复杂化。模型可以换规则、重排，也可以保持不变。规则正文由可信渲染器固定输出；自由理由与经验引用只保存作审计，不写入后续修订指令。

这样做有三个直接作用：策略变化可以逐项比较；评价时不会把模型在更新阶段生成的完整解答夹进策略；新策略可以在重置后的父状态上单独使用。代价也明确：规则集合与 `S0` 均由研究者设计，模型没有发明新规则，更新器本身也没有被改写。选择顺序是对模型的指导，当前没有强制执行每条规则的程序化流程，也不能仅凭输出理由就证明模型遵循了它。

## 2. 为什么选这两份经验与这两个评价起点

[状态盘点](2026-10-20-repair-state-inventory.json)覆盖四轮归档：58份源码副本实际对应36个源码哈希，其中34个来自模型、2个是手写弱起点。即使哈希不同，符号侧也有四份等价的线性形式、三份等价的三次形式。复制的起点、注释变化和同一轨迹中的连续候选均不能当作独立任务。

本轮选取有完整原始记录、诊断和来源绑定的状态，避免为了取得起点分数再执行旧候选。下表中的成绩均为旧开发记录，完整哈希和全部输入文件哈希见运行配置。

| 角色 | 真实归档状态 | 已观察到的情况 | 选择理由 |
|---|---|---|---|
| 更新经验 U-P | [P1-r1-checked 子程序](../../artifacts/paired-repair/2026-10-20/v01/P1-r1-checked/candidates/planning-001.py)，`fedb9ca6…` | 父、子均0/10；子程序在两个公开例中各返回11步，但首步输出格式即不合法、执行动作数为0。预测增加至少2个成功题，实际增加0。 | 提供“修改了内部逻辑，但没有消除最早可观察失败”的经验。计划长度的窄主张成立，并不证明输出合法或理由正确。 |
| 更新经验 U-S | [S1-r1-checked 子公式](../../artifacts/paired-repair/2026-10-20/v01/S1-r1-checked/candidates/symbolic-001.py)，`c73538e1…` | train NMSE从0.09639217降到0.09588858；实际下降0.00050359，未达到事前预测的0.002。 | 提供“确有小幅改善，但预测幅度与机制解释缺乏充分支持”的经验。它不是执行失败，也不是误差变差。残差分箱的一个数值比较成立，不能认证整段物理解释。 |
| 评价起点 E-P | [diagnostic planning_B003](../../artifacts/diagnostic-comparison/2026-10-20/planning_B/planning-003.py)，`2f98dbb2…` | 0/10；两个公开例均执行7个合法动作后，试图沿不存在的 `gate → location4` 有向边行走。 | 与U-P的输出格式问题不同，需要保持环境规则并重新组织行动；检查学到的修订优先级能否用于另一类实际错误。 |
| 评价起点 E-S | [diagnostic symbolic_C002](../../artifacts/diagnostic-comparison/2026-10-20/symbolic_C/symbolic-002.py)，`eea9556f…` | 三参数线性加截距形式，train NMSE为0.09591726；整体残差均值接近0，但不同速度分箱的误差仍不均匀。 | 与U-S的父、子公式不同，可检查策略怎样处理“总体偏差已消除，但仍有局部误差”的修订状态；分箱差异本身不指定正确的新项。 |

两份更新经验都来自上一轮已经实际执行的修订和未兑现的预测，便于把“观察—解释—编辑—预计变化—实际变化”连起来。它们同时提醒系统区分窄检查与整体解释。这里只把这些现象作为学习材料；单个失败预测不自动证明某条策略具有因果作用。

两份评价起点来自更早的 diagnostic-comparison B/C 会话，更新经验来自 checked-feedback-v02 延续出的 paired-repair 会话。选择的源码不重合，评价目标没有出现在更新经验的父子链中。但共同任务、弱起点与部分等价线性祖先仍存在，不能据此称信息完全独立。

`parent_id` 只记录当时被选中的 incumbent。模型可能已经看过同一会话中被拒绝的候选与反馈，因此盘点同时保留信息历史，不能只沿 `parent_id` 判定祖先关系。尤其不会把 paired 轮已经成功的规划兄弟程序、低误差的交叉项公式，或 E-S 后续的 C003，提供给更新器。

## 3. 经验如何被隔离，三种条件各回答什么

[状态加载器](../../rsi_eval/policy_cases.py)分别生成更新卡和评价状态。更新卡只含父子指标、原始理由、计划回放或训练残差的固定投影，以及剥离完整身份引用后的检查结果；不含完整源码、执行 trace、源码哈希、私有路径、评价状态或后续答案。原始理由是被分析的历史文本，不是系统指令，其中可能含少量变量名或公式片段，不能声称“完全不含代码词汇”。

评价时直接复制指定父产物的原始分数与诊断，不重算旧起点；每个条件只提出并执行一个新候选。评价包不携带该状态的旧历史声明或后续候选。更新器一次选出 `S1`，保存并冻结；评价阶段在新进程中检查冻结记录，评价成绩不能回流改写或挑选本轮 `S1`。

| 条件 | 修订策略 | 额外经验卡 | 主要比较用途 |
|---|---|---|---|
| `fixed` | `S0` | 无 | 固定人工初始策略下的一步修订参照。 |
| `memory` | `S0` | U-P、U-S两卡 | 检查直接在上下文中增加相同历史经验，是否已能改变修订；这里的“记忆”是固定结构化摘要，不是完整轨迹检索系统。 |
| `updated` | 冻结的 `S1` | 无 | 检查经验经一次规则选择与排序后，单独留下的持久策略是否影响其他父状态。 |

三种条件都看见完整规则目录，以及相同的当前源码、任务、诊断和证据 ID。变化限于 `repair_policy` 与 `experience_memory` 两个字段，因此 `updated` 并没有独占一条其他条件根本不知道的人工规则，而是改变明确要求执行的四条规则及其优先顺序。

`updated` 对 `fixed` 比较一次已冻结的策略选择；`memory` 对 `fixed` 比较直接呈现经验；`updated` 对 `memory` 比较本轮两种经验使用方式。最后一项不能解释成只隔离了“抽象化”这一单独因子：两组上下文长度不同，`updated` 还付出一次更新调用成本。必须报告实际输入、使用量和更新成本，不能称为等token或严格等总计算比较。

两次抽样用于观察同一策略、同一状态下生成结果的差异，**没有重复学习两份独立的 `S1`**。如果 `S1 == S0`，则如实记录 `no_op`；不能因为保存了一个文件就称策略实际改变。

## 4. 与已有论文的关系

**ExpeL，AAAI 2024。** 原文从经历中维护自然语言规则，包含 `ADD / EDIT / UPVOTE / DOWNVOTE`，并检索成功轨迹帮助后续任务。本轮只借用“经验—持久规则—后续应用”的分离思路，没有实现原版编辑操作、成功轨迹检索或原论文评测。依据为方法§4.2—4.3及Fig.2/3。[正式记录](https://ojs.aaai.org/index.php/AAAI/article/view/29936)，[本轮复核的arXiv v3正文](https://arxiv.org/html/2308.10144v3)。

**GEPA，ICLR 2026。** 原文在固定权重下根据执行与评价反馈修改提示，并结合候选池及Pareto选择。本轮借用反馈指导外部提示变化、再观察新提示行为的思想；没有运行其完整变异、交叉、候选搜索和验证选择流程，不能称为GEPA复现。依据为本地正式论文文本§3—3.1。[正式论文记录](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html)，[arXiv标识](https://arxiv.org/abs/2507.19457)。

本轮主流程已核对ExpeL官方页面及上述arXiv方法段；本说明复用该核查和[已有本地比较](../research/rsi-mechanism-review-2026-10-15/补充C_经验记忆与技能更新.md)。GEPA方法段本次直接重读用户提供PDF的本地文本提取，题目与ICLR 2026页眉一致，来源与哈希在既有交接包中记录；本轮OpenReview遇访问验证，未由该页面取得全文。这些访问状态不等于独立复现论文结果，也没有把预印本与正式版的全部内容逐项对照。

两篇论文说明这种研究组织方式有成熟参照，不会自动使我们选择的两份状态具有代表性，也不证明人工规则选择具有新颖性。本轮新增的是一条可审计的策略更新与异状态使用路径；长期贡献仍需针对稳定的失败条件、成熟方法对照和独立评价建立证据。

## 5. 本轮允许与不允许的结论

可以检查：是否产生了与 `S0` 不同且合法的规则顺序；冻结后是否确实在两种评价环境中使用；三组从相同父状态出发的提交率、改善与退化、检查质量、预测误差和成本分别如何。规划通过数与符号NMSE各自报告，不相加制造一个总体分数；无候选时连续质量指标留空，并单列“提交且改善”为假。

这些数据全部已被研究者看过，案例挑选也由研究者完成。Spanner仍是同一批10个公开/开发实例，符号侧仍是同一 oscillator1 训练数据，没有封存评分、跨方程或跨规划域的评价。两种经验又同时参与了同一次更新，因此不能将结果解释为“只从规划学得的策略迁移到符号发现”。同一机制接口能在两类任务上运行，与证明普适改进能力是不同结论。

如果本轮完成但没有改善，它仍能明确指出失败落在哪一段：有限规则选择没有发生变化、规则与新状态不匹配、生成没有落实修改，或修改本身无效。后续应据完整轨迹决定是否扩展独立更新重复和状态池，再设计与规则设计/选择均隔离的评价；不能只把这两个状态反复抽样后称为泛化证据。
