# 基函数策略开发对照 v0.2：决策 ID 与归档文字解耦

日期：2026-10-22。本文是新版本的实施协议与执行前验收要求，不是本轮真实完成记录。v0.2 保持[原 13 请求科学设计](2026-10-22-basis-trial-design.md)的任务、起点、策略目录、完整学习材料、位置顺序和数值评价，只修改提交接口及相应提示、记录和审计。实际结果应另文报告，本文不能作为模型已调用或方法有效的证据。

## 为什么需要独立新版本

v0.1 的真实 `measured-v01` 只发出一次策略请求。模型正常返回四个合法且不同的 ID，但必填辅助 `explanation` 为 4,223 字符，超过冻结契约的 2,000 字符上限，整份提案被拒绝。因此该轮没有 S1 冻结、真实 CSV 装载、拟合、预测或后续 12 次 actor 请求。停止原因由原始响应和实际 SDK 离线回放核验，见[原轮结果](../analysis/2026-10-22-basis-trial-results.md)。

文字解释原本不会进入 actor，但其长度却阻止了合法规则选择被测量。v0.2 将执行所需的 ID 和可有可无的叙述放到不同通道。它不放宽 ID、结构编辑、预算、一次性接受或全局响应边界；也不把解释中的事实判断自动当作可信经验。原提案中的历史误读保持原样归档。

**原 v0.1 响应不追认，原轮不续跑，原规则不充当新 S1。** 新版本从完整的既定历史包重新发出一次提案，另开目录和独立账本。原轮已发生的用量和费用仍计入项目累计记录。

## 两种业务提交与宿主转换

| 阶段 | 唯一业务参数 | 必须满足的条件 | 模型自由文字 |
|---|---|---|---|
| 策略提案 `submit_policy` | `rule_ids` | 原八规则目录中的四个不同 ID，顺序有意义 | 可缺失，保存原始 assistant content，不进入策略或 actor |
| 公式修订 `submit_basis` | `feature_ids` | 原字典内四个不同 ID，含常数；保留或单换项 | 可缺失，保存原始 assistant content，不进入源码、反馈或后续请求 |

工具参数不允许 `explanation`、`summary`、`security_risk` 或其他附加字段。一个响应只能包含一个 choice、一个业务工具调用；重复 JSON 键、错误类型、多个调用、非法 ID、预算或结束标记异常仍会导致停止。Optional assistant content 必须为字符串、null 或缺失。完整标准化响应仍受 65,536 UTF-8 字节上限约束，输出上限仍为 8,192 tokens；“可选文字不要求局部长度”不等于无限输出。

冻结的旧基函数编译器仍要求 `explanation` 字段，因此在新控制器中显式生成兼容执行对象：保留模型的 `feature_ids` 原顺序，只附加下列固定宿主元数据。

```text
Host-generated execution payload; no model explanation is used.
```

原始业务对象、宿主生成的 `execution_payload`、转换收据及编译结果分别保留。收据注明 `explanation_author=host_authored`、`model_explanation_used=false`，绑定业务对象、执行对象、源码和结构的哈希。调度器在拟合前再次核对两份 ID 完全一致、说明为固定标记，不能任意替换 ID 或把模型原文作为旧编译器说明。模型没有提交该宿主说明，报告不能将其算作模型解释。

策略和 actor 的系统提示、工具 schema、原始响应解析器、SDK Action 与调度器都使用新边界。不能只修策略入口而让 actor 继续要求解释。历史包中的旧文字保持原资料身份，不按结果删选或因本次故障加入新解释。

## 科学设计保持哪些约束

模型固定为 MiniMax-M3，OpenHands SDK 为原 1.55.1 环境，权重不更新。问题仍是：在相同起点、训练反馈、字典、K 和允许操作下，从既定历史学习材料提出的一份 S1，是否比固定 S0 产生更有益的单步结构修订。

- 唯一真实任务为原公开 LLM-SR `oscillator1/train`，角色为 `learning`，输入顺序 `x,v`，目标 `a`；训练文件 SHA-256 为 `a846b36b931dee4e2335faf9fb4195a7a8d1b4e4430e915266ef45fcd2e07ee7`。其他任务、test_id 和 test_ood 不开放。
- 起点 A 为 `{1,v,x,xv}`，起点 B 为 `{1,v,x,x²}`；均为研究者预定的 K=4 结构，字典是两输入三阶以内的全部 10 个单项式。保持全部父项，或恰好一删一加；常数必留。没有增项条件。
- S0 仍为 `R03/R04/R06/R08`。S1 仅提出一次，从原八条规则选排四项；相同则记录未变化，不补抽、不替换，也不依据本轮成绩晋升为 S*。
- 学习包仍是原两个完整历史批次的 24 条转移、四个已见状态、全部不同源码及逐任务结果。代码复用原学习包构建器，只替换过时的调度文字和接口说明；没有加入本轮父分、旧未接受提案、v03 或数值诊断的后续结果。
- 先保存合法 S1 和已知 usage，冻结策略后才读取训练表并计算两个父基线。每父只有一份固定反馈，同父的六个 actor 请求共享该反馈，除策略字段外的完整请求应相同。子结构成绩、其他 actor 文字不回流。

固定请求顺序如下；臂、起点和重复号是宿主标签，不作为额外模型上下文：

| 位置 | 请求 |
|---:|---|
| 1 | 唯一 S1 提案 |
| 2—5 | A-r1-S0、A-r1-S1、B-r1-S1、B-r1-S0 |
| 6—9 | A-r2-S1、A-r2-S0、B-r2-S0、B-r2-S1 |
| 10—13 | A-r3-S0、A-r3-S1、B-r3-S1、B-r3-S0 |

沿用原固定系数拟合器、全 1 初值、隔离环境、独立无 y 预测、宿主 NMSE 评分和残差摘要。固定 K 不代表相同表达能力、有效秩、条件数或计算开销。每份合法提交，包括重复相同结构，均在其预定位置拟合/预测一次，不事后去重、择优重跑或只报最佳。

## 限额、冻结及停止规则

最多 13 个模型请求，每位置一次，超时 180 秒，provider 和控制器重试均为 0；单次输出 8,192 tokens，预算请求 JSON 上限 98,304 字节；本轮累计保守预留上限 4 元。沿用原费率估算并保存实际 usage；费用估算和预留都不冒称服务商实际账单。历史两笔未知 usage 继续保留，项目 300 元上限仍有效。

最多 14 次真实拟合和 14 次独立预测，即两个父基线加 12 个子结构，总计最多 28 次真实任务 sandbox。假 provider、人工测量占位、内部人工 warmup 和离线审计分别列账。

任何非法提交、未知 usage、预算/输入超限、超时或传输异常、上下文变动、基线或候选执行失败均立即停止后续位置。停止原样保存；不恢复、不补抽、不修复原响应后继续。

新冻结包必须包含原 v0.1 全部运行依赖与 `extensions/basis_trial_v02` 新文件的哈希并集。原 v0.1 冻结清单和代码不修改。新准备包、新预演和新真实目录分别为：

```text
docs/experiments/basis-trial-v02-preparation/
runs/basis-trial-v02/sdk-preflight-v01/
runs/basis-trial-v02/measured-v01/
```

只有同一冻结版本的实际 SDK 假 provider 全流程通过、原始请求/响应/转换/接受/测量核对通过并产生匹配 readiness 后，才可在干净工作树启动独立真实目录。准备包或旧轮 readiness 均不能替代新验收。

## 执行前应验收什么

1. 两入口均接受 ID-only，均拒绝附加业务字段；可选 assistant content 缺失、空或超过原 2,000 字符时，合法 ID 仍按全局界限处理。使用原故障作为离线夹具，不把转换后的旧响应计作新研究接受。
2. 真实 SDK Conversation、Action、Executor 和一次性回调完整跑通 13 个模拟位置，覆盖两次合法单换项和十次保持，产生 14 次明确标注的人工测量占位；没有实际 provider 调用或真实 CSV 读取。
3. 原始 business、宿主 execution_payload、转换收据、编译源码及实际拟合对象逐项一致；可选文字不进入实际执行或后续 actor。
4. S1 先冻结、两父反馈先固定、位置/预算/失败即停守卫、同父请求只差策略、篡改拒绝及原冻结文件不变均有证据。
5. 最终审计从保存预测重算真实分数时只读已执行的授权训练表，不重新拟合候选；所有预定位置和缺失都保留。

验收通过只说明链路可运行。最终分析仍需分别展示两个父状态、两策略三次结果、保持/替换、独特结构数、NMSE、相对父基线改善和实际计算量。绝对阈值仍为 `1e-5`，不是显著性检验。若 S1=S0，差异只能作为同策略生成波动解释。已见训练数据、两个相关起点和每组 3 次生成不能支持独立泛化、稳定 RSI 优势或规则级因果归因。
