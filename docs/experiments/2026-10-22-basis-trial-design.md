# 固定 K 基函数修订：13 请求开发对照设计

日期：2026-10-22。本文在本轮真实模型请求和父结构拟合之前规定问题、起点、信息、顺序与上限。它不是执行完成记录；实际运行还须冻结对应源码、提示、数据身份、完整 SDK 请求模板和验收结果。依据为[基函数接口结果](../analysis/2026-10-22-basis-contract-results.md)及[独立结果审查](../analysis/2026-10-22-basis-contract-independent-results.md)。

## 本轮问题与定位

在相同有限单项式字典、K、父结构和训练反馈下，从固定历史材料提案的策略 S1，相比固定 S0，是否产生更有益的一次结构修订？本轮只比较一份策略提案，不依据本轮同任务成绩晋升 S1，也不产生 S* 或独立正式评价结论。

模型固定为既有 MiniMax-M3；OpenHands SDK 固定为 1.55.1。模型权重不变，策略表示仍为原八条通用规则中四条规则的有序选择。新基函数工具消除了任意 Python、重复参数乘积和自报参数数的自由度，但没有使不同特征集合的表达能力、设计矩阵秩、条件数或实际计算量相同。

## 任务与两个预定起点

唯一任务是公开原始 LLM-SR 的 `oscillator1/train`，按原角色表使用 `learning`。输入顺序为 `x, v`，目标为 `a`，元数据为 10,000 行。文件路径为 `data/symbolic/llm-sr/oscillator1/train.csv`，SHA-256 为 `a846b36b931dee4e2335faf9fb4195a7a8d1b4e4430e915266ef45fcd2e07ee7`。数据角色和身份沿用 [strategy-partition-v0.1.json](../../configs/tasks/strategy-partition-v0.1.json)，实际装载必须由原 RoleExecutor 核验。官方 test_id/test_ood 和其余任务不开放。

两个父结构均由研究者在本轮成绩产生前指定，不是模型生成，也不是旧源码的逐字迁移。共同设计规则是“仿射骨架加一个二次项”，分别采用交互项和第一变量平方项；没有依据本轮拟合结果挑选。它仍包含研究者的既有知识，不能声称随机、盲选或独立任务抽样。

| 起点 | 固定特征集合 | 规范 feature_ids | K |
|---|---|---|---:|
| A | 1, v, x, xv | m_0_0, m_0_1, m_1_0, m_1_1 | 4 |
| B | 1, v, x, x² | m_0_0, m_0_1, m_1_0, m_2_0 | 4 |

字典固定为两输入、总次数不超过 3 的全部 10 个单项式。允许保持父集合不变，或恰好删除一项并加入一项；常数必须保留。增项、减少 K、多项同时替换和字典外算子均不允许。本轮不开展 add_one 条件。

## 策略来源与冻结顺序

S0 固定为 `revision-policy-v0.1` 的 `R03/R04/R06/R08`，目录及英文规则文本逐字复用 [revision_policy.py](../../rsi_eval/revision_policy.py)。S1 只提案一次，可保持 S0 不变；若相同，记录 no_policy_change，不补抽。策略解释只归档，不进入 actor，不作为可信因果解释。

学习材料逐字复用 [strategy_learning.py](../../rsi_eval/strategy_learning.py) 构建的完整两批历史投影：decision-replay 的 16 份与 edit-commitment 的 8 份终稿，共 24 条转移、四个旧状态、全部不同源码及逐任务结果。共享源码和测量按原哈希去重；不按收益筛选，不截断说明来让请求通过。该历史只涉及 Spanner seed0 十题与 oscillator1/train。不得加入本轮起点、基线或子结构成绩，也不另添 v03、八条件数值诊断等后来的结果。

原更新提示与完整学习包一并冻结，SDK 实际发送的完整请求也要检查字节上限。学习包中的旧源码注释、声明和解释是待分析资料，不是可执行指令或已成立的因果事实。

执行顺序固定为：

1. 冻结协议、完整历史更新输入、S0、两个人工父集合、字典/K/操作、actor 提示、位置顺序、预算、源码和依赖；完成完整 SDK 假 provider 预演。
2. 发出唯一 S1 提案请求。原始响应、已知 usage 和合法规则集合均通过校验后，先保存并冻结 S1；失败、非法或 usage 未知则停止，不能用 S0 替补完成剩余轮次。
3. S1 冻结后，才分别执行 A、B 的一次基线拟合和一次独立预测；生成并冻结两个父反馈对象。任何基线失败均停止。
4. 按下表执行 12 个 actor 位置；每个只读自己的父反馈，子结构成绩不回流给后续 actor 或 S1。
5. 原始记录闭合后统一审计和分析；不按本轮表现晋升 S1、不追加新策略或重复。

## 请求位置与信息控制

父反馈由可信宿主从该父的一次已保存拟合/预测生成，包含结构身份、train 范围、规范参数顺序、拟合参数、NMSE、收敛及有界残差摘要。残差摘要沿用 `symbolic_diagnostics.summarize_residuals`，从该次保存预测产生，不增加拟合。原始 CSV 行、完整预测数组、另一个父结构的反馈、子结构成绩和解释不发给 actor。任何边际残差关联仍只是待验证假设。

模型业务提交严格只有 `feature_ids` 和非空 `explanation`。宿主在载入数据或执行前按基函数契约验证原始 JSON、SDK Action、特征集合、K 和实际编辑差分。模型文字不能将 keep 改记为 swap，也不能用文字声明替代宿主评分。每份合法子结构只执行一次 fit 和一次独立 predict；重复相同结构仍保留其位置并执行，不事后去重省略或择优重跑。

## 数值执行、预算与停止规则

沿用已校准的规范源码生成、identity 输入转换、`nan_to_num(nan=0,posinf=1e6,neginf=-1e6)`、全 1 系数初值、NumPy 1.26.4、SciPy 1.13.1 和 `least_squares(..., max_nfev=100)`；每个候选仍在原 Bubblewrap/seccomp 资源边界内执行。独立预测不带 y，宿主计算 population-variance NMSE。

- 最多 13 个真实模型请求，每位置一次；单次超时 180 秒，自动重试和 provider 重试均为 0，单次输出上限 8192 tokens，完整预算请求 JSON 不超过 98,304 字节。
- 本轮累计模型费用的保守预留上限为 **4 元人民币**，复用既有预算估算费率和实际 usage 记录。预留不是服务商账单；账户及其他项目花费不由本账本控制。项目 300 元总上限仍有效，历史两笔未知 usage 不归零。
- 拟合最多 **14 次**：两个父基线加 12 个子结构；独立预测最多 14 次，共 **28 次真实任务 sandbox**。记录所有拟合尝试、失败、nfev、实际公式调用数与耗时。内部人工 warmup、人工测试和假 provider 请求另外计数。
- 非法提交、缺失工具调用、重复/多工具调用、结构越界、基线或候选执行失败、预算超限、超时、传输异常或 usage 未知均停止后续请求。失败原样保存，不追加修复请求，不补抽，不恢复同一轮；已发请求的预留不退回。
- 只有实际 SDK Conversation 的假 provider 全流程、传输边界、次数/顺序、严格接收、停止负例和冻结哈希核验通过，才能启动新真实目录。预演的模拟 usage 和人工成绩不计入研究账本。

## 分析与不能作出的结论

全部预定位置均列入报告，未开始、非法、缺失、拟合失败不填零分。对每个起点分别展示两策略的三次提交、实际保留/换项、结构唯一数、训练 NMSE、相对父基线的改善及计算开销；给出各组三次的均值、中位数、范围，以及六个同起点配对。不得只报最佳一次、挑较有利起点或删除失败位置。

采用绝对 NMSE 容差 `1e-5`：`parent_nmse-child_nmse>1e-5` 记本次有益修订，小于 `-1e-5` 记退化，容差内记无可观察变化。该分类是事先固定的开发判据，不是统计显著性检验。策略差异与结构变化也分别报告；S1==S0 时只解释为同策略重复生成差异。

三次生成共享同一数据和父结构，不是三个独立数据集；配对没有声称共享模型随机种子。两个起点也共享仿射骨架和同一训练表。该表与策略学习包有直接重叠，所有结果只能用于已见任务的开发判断。不得声称独立预测泛化、普适 RSI、稳定机制优势、规则级因果归因或新方法已经成立。

原规则目录包含偏规划或通用契约的守则，在受限符号选择中可能作用很弱。无改善需要检查策略实际是否变化、结构是否重复、有效信息是否不足；不能据此推出所有经验机制无效。若出现收益，也要与同策略生成波动和原父基线同时解释。本轮不把该任务成绩作为晋升依据，再用同任务分数冒充独立后续验证。

旧运行、旧数值诊断与人工校准保持原状，不恢复、不拼接、不改旧分。最终报告须另列真实研究活动、假 provider 预演、人工测试、离线审计以及实际未完成部分。

## 执行前独立源码审查

审查范围为新 `extensions/basis_trial_v01/run.py`、`feedback.py`、`sdk_controller.py`、`simulation.py`、`verify.py` 与相关负例测试，并与原角色执行器、预算、传输绑定和基函数契约交叉核对。审查未读取真实 CSV 数值、调用模型、拟合或修改执行源码。

审查确认，调度首先冻结唯一 S1，再经原学习角色装载 oscillator1/train；两父基线分别生成固定反馈，12 个 actor 不接收子结构反馈。四系数、一次换项、13 位置顺序和 4 元预算已在代码中绑定，旧代码保持原状。初审提出的 ID 指数语义、策略/上下文文件逐次哈希保护、失败测量计数、汇总策略与冻结绑定，以及真实运行末尾从已保存预测重算分数等问题，均已在本次冻结前修订。假 provider 全流程加入 A→B、B→A 两个合法换项，其余保留，以覆盖 keep 和 swap_one 两条路径；人工回复及假测量不计研究。

当前静态审查未发现需要阻止新冻结和完整预演的剩余问题，但这不是 SDK 新冻结版本预演通过的声明。开发期预演曾在执行完模拟位置后遇到宿主大汇总误用 64 KiB 响应解析上限的审计错误；该记录保留为工程调试，修复后必须新冻结、新目录预演，不能追认旧 readiness。正式验收以保存的测试输出、完整 SDK 预演、原始请求/响应/派发/测量绑定及外部冻结哈希为准。

原始 SDK 引用保存的是运行时项目相对路径。跨机复核应保留相同 `runs/...` 相对路径；另行复制至 `artifacts/...` 时通过完整清单核对逐字节一致，不改写原始引用以适配归档位置。运行目录审计与归档完整性核对须分别记录。
