# 基函数提交契约：独立设计审查

日期：2026-10-22。范围：审查新的 `extensions/symbolic_basis_v01` 设计，以及已存在的符号诊断、提交与执行代码；本文件不是实现验收或实验成绩。审查过程只读正式文件与源码，没有打开真实 CSV、执行候选、拟合、访问凭据或调用模型。

## 结论与设计目的

该契约适合作为下一项工程与研究控制：模型只选基函数，宿主确定参数顺序、生成直接系数形式并执行同一拟合器。它能消除模型自由提交冗余系数乘积、任意 Python 保护代码或自报参数数的空间，使“换了哪些项”成为可执行检查的事实。它不能自行证明所选项有益，也没有将不同函数族的表达能力、条件数或实际计算量变得相同。

证据来源是已完成的[八条件数值诊断](../analysis/2026-10-22-symbolic-numerical-diagnostic.md)：stress 同族直接系数取得近乎相同的训练误差但减少公式调用；bact 等 14 项的不同基函数组合也有明显训练误差差异。因此，先规范表示，再比较策略选择，有针对性的证据依据。本设计是在这些已见结果之后形成，不能把其后同两张训练表上的成功称为独立验证。

## 提交与宿主的权限边界

1. 模型业务字段仅为 `feature_ids` 与可选 `explanation`。输入维数、精确项数 K、任务身份、父版本、允许编辑类型、资源、数据、初始化和评分均由宿主绑定。禁止模型提交源码、系数、参数数、文件路径、任务角色或拟合设置。
2. 输入维数是严格整数 1 至 4；K 是严格整数，必须满足 `1 <= K <= min(16, 字典大小)`，并要求常数项。Python 的布尔值也是 `int` 子类，验证时需明确排除，不能只用 `isinstance(value, int)`。
3. 全部总次数不超过 3 的单项式数为 `C(d+3, 3)`，d=1/2/3/4 时分别为 4/10/20/35，包含常数项。字典 ID 应由宿主固定指数向量生成，输入变量顺序必须另行固定，不能解析模型提供的表达式字符串。
4. 重复 ID、未知 ID、不匹配的维数、遗漏常数、错误项数、额外字段和非字符串解释均应拒绝。对已验证的合法集合才作规范排序；不能通过去重、截断、补常数或丢弃额外键把非法提交修成合法提交。
5. 保存原提交及其哈希，同时保存规范集合、字典/任务规范哈希、生成源码哈希和宿主参数顺序。模型提交排列可以相异；规范源码必须相同，避免用浮点累加顺序制造隐蔽自由度。解释保持未验证文本，不作为成绩、接受理由或新的经验自动回流。
6. 后续接入 OpenHands 时，保留旧适配器已经解决的严格原始 JSON 检查：重复键、非法常量、类型强制转换、额外业务字段及多个工具调用要在 SDK 归一化前处理。SDK 宣告的可选元数据如 `summary/security_risk` 与业务字段应分离，并严格检验其实际 schema；不能重现“SDK 宣告允许、接收器却拒绝”的旧故障。若本轮只验收纯契约和沙箱校准，应明确尚未验收 SDK 实际请求往返。

现有参考为 [strategy_pair_controller.py](../../rsi_eval/strategy_pair_controller.py) 的 `strict_json/validate_arguments`，以及 [strategy_pair_agent.py](../../rsi_eval/strategy_pair_agent.py) 的原始参数检查和单工具请求约束。复用其原则不要求修改已冻结的旧运行文件。

## 固定项数编辑与增项需要分开记录

“固定 K”至少要验证父集合与子集合均合法、常数保留且项数相等；同时记录实际删除与新增的 ID。若实验定义为一次换项，还需精确满足一删一加；若允许多项同时替换，则报告替换数而不称为单项干预。完全相同的集合应有独立 `keep/no_change` 状态，不能用解释中“改进”二字替代实际变更。

“增项”应验证父集合为子集合真子集、指定的 K 增量和不超过 16 的上限。减少项数、换项并增项、或者违反固定 K 的提交，不能偷偷并入同一条件。若本轮只实现这些结构分类而未接入最终选择器，记录为契约能力，不能称策略接受规则已经冻结。

K 只控制名义系数数量。不同基函数集的函数族不同；同一数据上可能出现秩亏、共线性、尺度差异和近退化。不同次数的项也需要不同的乘法计算，不能把相同 K 或相同 `max_nfev` 写成等实际计算预算。系数等于零时也不能自动删项再更新 K；那是另一个显式简化步骤。

## 数值执行与信息暴露

- 保留当前全 1 初值、identity 输入变换、SciPy 版本与 `least_squares(..., max_nfev=100)`，便于将变化限制在表示契约。不同基函数组合在同为全 1 时整体初始预测仍不同，需保留这一限制。
- 直接系数在有限实数域构成线性参数模型；有限精度、保护操作与迭代停止仍可能影响结果。当前诊断继承 `nan_to_num(nan=0, posinf=1e6, neginf=-1e6)`，它在溢出点已经不是原多项式。新契约必须显式固定保护语义，并用极端有限输入校准；若改为拒绝非有限值，应当明确记为契约改变，不能声称逐字节或全输入等价。
- 不需要为了本轮改成闭式最小二乘或更强求解器。将来可将其作为独立宿主基线，但不能把换拟合器的收益归给 Agent。
- 拟合与预测分进程；预测请求不能含 y。宿主从允许的数据计算 SSE/MSE/NMSE，而不接受模型或候选的自报分数。解释中给出的数字不能进入评分链。
- `nfev` 不包括全部有限差分公式调用；同时报告真实公式调用数、沙箱耗时、终止标志、失败和预算耗尽，不能只报告成功条件。
- 字典小不等于无资源风险：三次幂仍可能溢出，行数和载荷仍需限制，20 秒/2048 MB/CPU 10 秒等现有边界仍需保留。可信源码生成只缩小了语言能力，不替代隔离和记录。
- 本轮人工校准数据与代码可公开；后续真实数据仍走原任务角色/哈希授权。不能因模型不再提交 Python 就让它选择 CSV 路径或跳过评价门禁。保存的预测或残差也不应未经预先定义就回传给下一轮选择器。

## 有意义的人工校准建议

下列是校准建议，不代表已经运行。一次校准应事前选定有界列表，逐项保存结果；失败不掩盖，也不将人工目标计为真实任务成绩。

| 情况 | 人工构造 | 要检查的独立性质 |
|---|---|---|
| 可表示目标 | 对称网格 x，目标 `2 + 3x - x²`，三项 `1,x,x²` | 宿主系数映射正确；独立预测恢复目标；目标方差非零 |
| 同 K 换项 | 同一目标、同 K=3，以 `x³` 替换 `x²`，保留常数和 x | 编辑分类是一删一加；正确结构能拟合，错误结构保留非零残差；差值由宿主重算 |
| 独立增项 | 从 `1,x` 到 `1,x,x²` | 增项单独分类；不能当固定 K 收益 |
| 混合项与维序 | 二维笛卡尔网格，目标 `1 + 2u0u1 - 3u1²` | 混合项指数、输入列顺序和系数顺序正确；不能只测单变量 |
| 规范排序 | 同一个合法 ID 集合以不同顺序提交 | 得到相同规范集合、源码及参数对应，不新增拟合来证明这一纯结构属性 |
| 退化设计 | 人工输入两列相同，同时含 `u0/u1` | 相同项数不保证唯一系数；只检查预测/残差，不断言系数恢复唯一真值 |
| 常数目标 | 合法常数目标 | 拟合可成功，但 NMSE 因零目标方差应明确不可用，不能记 0 或丢弃 |
| 非法提交/数值边界 | 重复/未知 ID、bool K、超上限、缺常数、额外源码键、重复 JSON 键、极端有限输入 | 结构非法时不进入沙箱；极端数值的实际行为与已声明保护一致 |

人工数学性质是独立预期，不能只断言实现又算出相同实现结果。真实沙箱校准应覆盖少数关键正负例；大部分 schema/规范化负例可用单元测试验证，避免把无需拟合的输入消耗混进 fit 计数。启动 warmup、人工 fit、人工 predict、fake-provider 请求及真实研究请求分别计数。

## 后续策略对照的因果与统计边界

1. 新契约将自由 Python 生成收窄为有限多项式基函数选择，是一个明确、可检查的结构搜索子问题。它未覆盖除法、指数、三角函数或其他新算子发现；不能仅凭沿用 LLM-SR 数据名将其称为完整原方法复现或一般符号发现。
2. 固定这一契约后，再冻结策略候选、历史学习包、起点、每臂反馈、接受规则和独立调用预算。每个比较臂使用相同契约与求解器。不能把旧任意源码成绩与新基函数成绩的差直接当作新策略收益。
3. “多次证据选择”与“单次证据选择”同时改变信息量和规则时，应按原设计 B 的边界报告。共享收集结果并不使两者独立运行成本相等。相同输入下的重复生成、策略内容重复和同策略两臂均要保留。
4. 所有四任务的 train 已有不同程度使用，本轮最优平方项来自已见诊断。后续的新程序起点是新状态，不自动是新任务或独立数据。官方封存集的用途、打开时机、一次性最终评价和训练数据内选择应另行冻结。
5. 单次拟合没有随机优化稳定性证据；一个领域及四个方程没有广泛任务分布推断基础。重复 Agent 生成能够估计条件于既定任务/学习包的变化，不能把它们当作独立数据集样本。

本审查支持完成契约与人工校准，再将其作为新的策略试验准备条件。它不支持本轮直接执行尚未冻结的 168 请求草案，也不支持仅凭工具测试通过宣布 RSI 机制有效。

## 实现审查：执行器与人工校准

本节只读审查 `extensions/symbolic_basis_v01/executor.py`、`calibrate.py`、`contract.py`、`test_executor.py` 和所绑定的旧沙箱工作器；未运行候选或拟合。审查发生在执行前开发期，下面指出的缺口需由实现者修复并以实际测试确认，本节本身不是其后版本已经通过的证明。

已在源码核实的约束：

- `validate_transition` 在建立输出目录或装载角色数据前检查合法结构；`swap_one` 只允许原样或一删一加，`add_one` 要求真增一项且保留全部父项。当前实现区分了 keep、换项与增项。
- `evaluate_submission` 先验证维数、有限数值和至多 20,000 行，然后先写 reservation 再调用一次拟合；只有合格拟合结果才发起预测。预测请求重新构造并移除顶层 y，独立沙箱接收拟合系数；评分由宿主完成。拟合失败不自动补抽。
- `evaluate_role` 复用旧 `RoleExecutor` 的数据角色与冻结门禁，没有把目录或角色作为模型业务参数。新模型业务契约当前是对象接口；尚不能由此声称 OpenHands 原始 JSON/schema 和实际 SDK 往返已完成验证。
- 校准列表固定 9 个拟合条件：一维仿射、二维混合、三变量乘积、四维混合、缺平方项、同 K 换项、增一项、常数目标、共线输入。另有两条仅预测的 overflow guard 条件。完整成功路径应为 9 fit + 11 predict = 20 次沙箱启动；warmup 也应单独计为 20。常数目标预期是拟合成功但 NMSE 不可用，处理方向正确。共线输入只要求正确预测，没有要求恢复唯一真系数。
- 当前人工校准覆盖 d=1..4 与多种编辑/保护语义，但真实沙箱所用最大 K 是 4；它不能额外证明 K=16 时的数值稳定性或资源裕量。无需因此临时增加已冻结条件，只需准确描述覆盖范围。

执行前发现的主要核验缺口如下，已即时报告主代理：

1. 首次所读 `verify` 未从固定 fixture 重建并核对 `transition.json` 和结果中的 transition。结构文件哈希正确只能说明当前 manifest 与当前文件一致；若修改该文件并重算 manifest，错误的编辑分类仍可能通过。
2. 两条 guard 条件只重放预测值，未核对各自 `compiled.json/request.json` 与固定规则生成的源码、输入和参数。应验证它们确实对应预定的 `m_0,m_3`、`[1e200,-1e200,0]` 与两组指定系数，并要求预测回执的完成和成功状态。
3. 首版 `verify` 对拟合/预测原回执未完整重放执行器成功条件，也未核对全部 reservation 字段、逐条件 fit/predict 计数和 summary 活动字段。应从固定 fixture 和合格回执重建 9 次 fit、11 次 predict、20 次 sandbox/warmup，并检查模型/真实数据/封存计数为零；不能只检查文件数量与 `summary.sandbox_calls`。
4. 输入数值边界较严格；`input_names` 当时只检查列表长度、`task_id` 没有显式类型/长度检查。这些参数由可信宿主传入，固定人工 fixture 与旧角色装载器使用正常字符串，当前校准未见可利用的数据暴露路径。但若该准备数组接口将来接收其他调用方，建议严格限制元数据类型并只向预测器传递必要字段，避免把任何任意嵌套元数据也随请求透传。不要将“删除顶层 y”推广为“任意宿主输入均不可能携带目标信息”。

修复核验时，建议增加重算 manifest 后的负例，至少覆盖结构编辑分类、guard 输入或源码、回执状态、逐条件次数和汇总次数。这些是离线证据一致性测试，不需要再次执行任何候选或拟合。即使这些检查全部通过，也只能证明记录内的一致性与绑定，不能抵抗所有文件及外部锚同时被协同篡改，更不能提供硬件级执行证明。

## 执行前复查：修复与覆盖扩展

主代理在协议冻结前完成修改后，本审查再次只读查看执行器与校准器，确认以下实现已经存在。此处“确认”指源码确认，不代表真实数值校准已经执行；最终运行证据由独立的校准原档和验收文件提供。

- `verify` 已从固定 fixture 重建 transition，核对 `transition.json` 与结果内同名字段；reservation 改为全字段相等；两条 guard 的源码编译产物、输入及系数请求均重建核对，并要求预测成功状态。
- 拟合与预测回执的完成/成功标志、收敛、nfev、公式调用数、优化器诊断关联、逐条件 2/1/1 次数，以及汇总的全部研究/人工活动计数已有显式校验。该修改补上了首次审查中最主要的记录一致性缺口。
- 宿主元数据现在要求输入名为互不重复的有限长度标识符，task_id 为有限长度字符串；不再接受嵌套数组或对象作为这些字段。
- 冻结前人工列表增加 `max-k-4d`：四维完整的 15 个二次以内项，加 `u0³`，达到允许的 K=16。目标通过单独的闭式表达式构造，不读取候选预测作为真值。因此成功路径更新为 **10 次人工 fit + 12 次人工 predict = 22 次 sandbox/warmup**。上节的 9/11/20 数字和“最大 K=4”描述仅记录首次开发审查版本，由本段的最终拟定列表取代。

本次复查另提出两项小补强建议：在离线 `verify` 中显式重放执行器已有的系数列表长度/类型/有限性检查，不能只确认 fit/result/diagnostics 中几个列表相等；零方差导致 metric_unavailable 时应要求 metrics/SSE 为空，防止无效成绩字段残留。它们不需要额外候选执行或拟合。K=16 人工样例即使通过，也仅证明该指定网格与目标下的接口/求解路径，不证明所有真实数据的数值稳定性或资源裕量。
